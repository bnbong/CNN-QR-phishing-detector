## 0. 결론 요약 — RQ1 ~ RQ3

| 연구 질문 | 현재 답 |
|---|---|
| RQ1. 길이·버전·패딩 shortcut을 통제한 뒤에도 QR 모듈 격자에 phishing-discriminative signal이 있는가 | 그렇다 (2절, 6-1). 캠페인·템플릿 단위로 잘라낸 홀드아웃에서도 유지된다 (11절) |
| RQ2. CNN은 명시적 디코딩 없이 공간 배치를 이용해 URL 유래 내용·순서 신호(URL-derived content/order signal)에 접근하는가 | 접근한다. 다만 사용한 선형 프로브와 판정 기준으로는 경로 구조 특징 두 개 말고는 어휘 정보의 선형 접근성도, 학습에 의한 접근성 향상도 확인하지 못했다 (3절, 6-2·6-3, 5-B절) |
| RQ3. 그 신호가 여러 피싱 QR에 반복되는 국소 motif로 나타나며 새 도메인·데이터셋에서도 재현되는가 | 앞부분은 절반이다 — 국소 motif는 존재하지만 "그 motif가 CNN 판단의 원인"이라는 이전 결론은 개정된 절제 설계에서 지지되지 않는다 (7절, 5-A절). 뒷부분도 약하다. 길이와 경로 모양을 함께 맞춘 cohort에서 전이 AUROC가 0.639 ~ 0.677로 순열 바닥선(0.53 ~ 0.56) 위에 남지만 텍스트 기준선이 더 잘 전이되고 개별 motif의 정체는 재현되지 않는다 (10절) |

지금 안전하게 말할 수 있는 선은 여기까지다. 길이, QR 버전, 패딩 경계, 그리고 일부 표면적 URL shortcut을 통제한 뒤에도 피싱과 정상 QR 모듈 격자 사이에는 판별 가능한 신호가 남는다. CNN은 QR의 원래 공간 배치를 활용한다. 3×3 국소 패치 빈도 분포(local patch-frequency distribution)에도 클래스와 연관된 구조가 들어 있고, 그 구조는 바이트 조성만으로 재현되지 않는다. 반면 사용한 선형 프로브와 판정 기준으로는 개별 URL n-gram이나 키워드의 복원 증거를 확보하지 못했다.

이전 결론 하나를 철회한다. 옛 문서는 "특정 motif 위치를 겨냥한 중심 비트 개입이 개수·위치·밀도를 맞춘 무작위 개입보다 큰 성능 저하를 일으킨다"고 적었다. review_03 2·3절이 지적한 두 결함(여러 시드의 train을 합쳐 motif를 고른 뒤 그 목록을 모든 시드의 test에 쓴 것, 그리고 무작위 대조만 반복 예측의 로짓을 평균한 뒤 AUROC를 계산한 것)을 고쳐 다시 재니 그 간격이 사라졌다. 시드별 train 선정·같은 시드 test 절제·반복별 AUROC로 계산한 ΔΔAUROC(표적 − 개수 맞춤 무작위)는 v2 +0.000 [−0.006, +0.006], v3 −0.009 [−0.017, −0.001], v4 −0.002 [−0.018, +0.014]다. topology 맞춤 대조와의 대비도 CI가 0을 포함하거나 경계에 걸린다. 표적 개입 자체의 ΔAUROC(−0.014 ~ −0.045)는 무작위 개입(−0.014 ~ −0.033)과 같은 크기다. 옛 결과는 로짓 평균 대조와 시드 통합 선정이 만든 인공물이었다. 이 반전은 외부 리뷰의 방법론 지적을 코드에 적용해 스스로 잡아낸 것이고, 결론이 어느 절차에 얼마나 의존했는지를 보여 주는 기록으로 남긴다.

외부 검증과 캠페인 홀드아웃까지 끝난 지금, 일반화에도 답이 생겼다. 2026년 OpenPhish 피드와 Common Crawl benign으로 만든 외부 세트에 WebPhish 모델을 그대로 걸면, 길이만 맞춘 cohort에서 AUROC가 0.744 / 0.702 / 0.693이다. 그런데 같은 cohort에서 경로 모양만 쓰는 path-shape LR이 v2 0.780으로 CNN에 근접한다. 경로 shortcut이 전이 점수의 상당 부분을 만들고 있었다는 뜻이므로, 길이와 경로를 함께 맞춘 cohort를 주 판정으로 삼는다. 거기서 CNN은 0.649 / 0.639 / 0.677로 내려가고 path-shape LR은 0.39 ~ 0.54로 무너진다. 순열 바닥선 0.53 ~ 0.56은 여전히 넘으므로 신호가 사라진 것은 아니다. 판정은 v2 `partial_collapse`, v3·v4 `reproduced_weak`다. 같은 외부 데이터로 학습하면 0.87 ~ 0.93이 나오므로 신호가 없어서가 아니라 전이가 안 되는 것이다. 다만 char n-gram LR은 매칭 후에도 0.71 ~ 0.83으로 CNN보다 잘 전이된다(쌍체 Δ = CNN − char n-gram이 −0.09 ~ −0.24). 개별 motif의 재현은 더 나쁘다. 고정 cohort primary에서 512종 log OR의 Spearman ρ가 0.228 / 0.066 / 0.073이다. 상위 20 Jaccard는 귀무 수준이다. 분포 수준의 신호는 약하게 전이되지만 개별 motif의 정체는 데이터셋 특이적이다.

아직 쓸 수 없는 문장도 그만큼 분명하다. "피싱 QR에 보편적인 시각 signature가 존재한다"는 주장은 외부 검증이 끝난 지금 지지되지 않는 쪽으로 답이 나왔다. "CNN이 QR에서 URL 어휘를 복원한다"는 주장은 사용한 프로브와 기준으로 복원 증거를 확보하지 못했다는 데까지이며, 복원 자체가 기각됐다는 뜻은 아니다. "특정 motif가 CNN 판단의 원인이다"는 주장도 현재 절제 설계로는 지지되지 않는다.

증거의 강도는 단계마다 다르다.

| 주장 | 현재 증거 |
|---|---|
| QR 모듈 격자에 클래스와 연관된 정보가 남는다 | 강하게 지지 (2절) |
| 원래 QR 공간 배치가 CNN의 분류에 도움이 된다 | 강하게 지지 (3절) |
| 클래스와 연관된 국소 패치 빈도 분포(class-associated local patch-frequency distribution)가 존재한다 | 지지 — 3×3 히스토그램 LR이 라벨 셔플 바닥을 뚜렷이 넘는다 (7절) |
| marginal bit/byte composition으로 설명되지 않는 국소 공간 의존성이 존재한다 | 지지 — QR 안에서 모듈 위치만 섞으면 3×3 히스토그램 LR이 0.740/0.707/0.715에서 0.498/0.502/0.510으로 라벨 셔플 바닥까지 무너지고, 바이트 조성을 그대로 보존하는 코드워드 셔플에서도 0.547/0.539/0.555에 그친다 (7절) |
| 그 motif가 CNN 판단에 인과적으로 기여한다 | 지지되지 않음 — 시드별 선정·반복별 AUROC로 고쳐 재면 표적 개입과 개수 맞춤 무작위 개입의 ΔΔAUROC가 +0.000 [−0.006, +0.006] / −0.009 [−0.017, −0.001] / −0.002 [−0.018, +0.014]이다. 이전의 "인과 기여" 결론은 철회한다 (5-A절) |
| CNN 내부에서 URL 문자·n-gram 자체가 복원된다 | 사용한 프로브와 기준으로 복원 증거를 확보하지 못했다 — 시드별 정확 판정에서 셔플 기준선을 넘은 목표가 v2 2개(`has_path`, `path_depth`), v3·v4 0개이고 그 둘은 어휘가 아니라 경로 구조 특징이다 (5-B절) |
| 이 패턴이 다른 피싱 데이터에서도 일반화된다 | 약하게 지지 — 경로 shortcut까지 통제한 주 cohort에서 전이 AUROC 0.649 / 0.639 / 0.677이 순열 바닥선 0.53 ~ 0.56 위에 남지만, 텍스트 기준선이 더 잘 전이되고 개별 motif 정체는 재현되지 않는다 (10절) |
| 성능이 phishing kit·템플릿 누출에서 온다 | 전체 AUROC 상승은 SESOI 0.02 아래로 한정했다(주 지표 세 층 `negligible`, CI 상한 0.0011 / 0.0145 / 0.0151). 누출 기회가 있는 행(38 / 35 / 15)만 보면 검출도 배제도 못했다 (11절) |

여기서 "visual"은 raw-image의 시각 패턴이 아니라 정규화된 QR 모듈 격자의 공간 패턴을 가리킨다. 입력은 완벽히 정렬된 2채널 비트 격자다. 촬영·인쇄·회전이 개입하는 실제 QR 이미지 이야기는 이 문서 범위 밖이다. 연구 대상은 정확히 정규화된 URL 문자열에서 합성한 QR 격자다. 전체 소문자화와 말미 `/` 제거가 경로·쿼리의 의미를 바꿀 수 있다는 점도 범위 안에 들어 있다.

2차 실험 B(Bag-of-QR-patches, 7절), C(인과 motif 절제, 5-A절), D(어휘 프로브, 5-B절), 개정 Grad-CAM(5절), H1 ~ H4 가설 검정(5-C절), F(외부 검증, 10절), G(캠페인 단위 홀드아웃, 11절)를 모두 실행했다. review_03의 지적을 반영한 재실행(시드별 motif 선정, 반복별 AUROC 대조, 길이+경로 매칭 cohort, 순열 2,000회, 5시드 쌍체 기준선, 시드별 프로브 판정)도 끝났다. F 중 F-c(역방향 전이, 외부 학습 → WebPhish 평가)와 F-d(혼합 학습)는 미실행이다. 노트북 실행 인자가 `modes=("a","b")`였다.

## 1. 실험 요약

- **데이터**: WebPhish(Opara et al., 2024). URL 정규화(소문자화, 선행 `www.` 1회 제거, 말미 `/` 제거)
  후 중복·라벨 충돌 제거. QR 생성 조건은 EC=L, `optimize=0`(단일 8비트 바이트 청크), `mask_pattern=0` 고정.
  모델 입력은 PNG가 아니라 `(2, n, n)` 비트 격자(값 채널 + 데이터 모듈 마스크)다.
- **층**: QR 버전 v2/v3/v4가 primary(엄격 길이 매칭 후 클래스당 ≥1,000). v5+는 매칭 후 클래스당
  266개만 남아 사전 등록 규칙대로 **폐기**했다. 따라서 이 문서의 결론 범위는 URL 길이 18 ~ 78바이트 구간이다.
- **표본 수**(주 조건 `L-exact`): v2 12,118 / v3 9,178 / v4 2,714, 층 안에서 두 클래스 1:1.
- **분할과 통계**: eTLD+1 그룹 그리디 빈패킹 70/15/15, 단일 그룹 5% 상한 다운샘플. 시드 5개(0 ~ 4)를
  분할·서브샘플·초기화에 함께 걸어 평균과 SD를 낸다. 95% CI는 표본이 아니라 **그룹을 리샘플링하는
  시드 층화 클러스터 부트스트랩**이다. 부트스트랩 반복마다 eTLD+1 그룹을 리샘플링하되 AUROC는
  시드별로 따로 계산해 평균하므로, 시드 간 점수 척도 차이가 통합 추정치를 끌고 가지 않는다
  (`reports/*`의 `pooling: seed_stratified`).
- **누출 진단**: `reports/split_diagnostics.json`의 12개 층 셀 전부에서 split 간 eTLD+1 교집합이 0이다.
  test 상위 5개 그룹이 차지하는 비중은 18.7 ~ 20.6%다.
- **역매핑 게이트**: 통과(1,584건 검사, 실패 0). 모듈 ↔ 비트 ↔ 코드워드 ↔ URL 바이트 역매핑이
  라운드트립으로 검증되지 않으면 학습 자체를 돌리지 않는다.
- **디코딩 텍스트 참조 기준**: 모든 조건·층에서 CNN AUROC가 char n-gram LR(디코딩 텍스트 참조 기준)
  아래였다. 이 참조 기준은 **강한 텍스트 베이스라인**일 뿐 Bayes 최적 분류기가 아니므로 상한선이 아니며,
  넘더라도 누출의 증거가 되지 않는다. 따라서 부호 있는 갭(`gap_to_decoded_text` = 참조 − CNN)만 보고하고
  누출 판정용 부등식 검사는 두지 않는다. 누출 진단은 라벨 셔플 바닥과 split 진단이 담당한다.
- **하드웨어**: Colab T4 단일 GPU.

작동했다는 확인이다. 층 안에서 버전이 고정이고 길이 주변분포가 클래스 간 동일하므로 두 변수는
정의상 라벨 정보를 갖지 않는다.

## 3. H4 — 공간 구조 검정

`shuffle-pos`는 모든 표본에 동일한 고정 순열을 걸어 픽셀 값 집합은 그대로 두고 위치 정보만 파괴한다.
BitMLP는 대조군 역할을 한다. 정확히 말하면 MLP 자체가 순열 불변인 것이 아니라, 재학습되는 MLP의 가설 공간이 입력 좌표의 고정 순열에 대해 표현력이 동등하다. 같은 가중치에서 f(Px)=f(x)가 성립한다는 뜻이 아니라, 순열된 입력으로 다시 학습하면 원래와 같은 성능에 도달할 수 있다.

| 조건 | v2 | v3 | v4 |

## 5-A. 인과 motif 절제 (C)

7절에서 뽑은 층별 상위 motif가 실제로 CNN 판단의 원인인지 본다. 개입의 이름은 motif 표적 중심 비트 개입
(motif-targeted center-bit intervention)이다. 절차는 이렇다. test 표본의 데이터 모듈에서 상위 motif와 일치하는
3×3 창을 찾고 매칭된 3×3 창의 중심 모듈 하나만 뒤집는다. 창 전체를 바꾸는 것이 아니라 창당 모듈 하나를
바꾸는 것이므로 "motif 뒤집기"라는 표현은 쓰지 않는다. 매칭은 원본 격자 한 벌에서 모두 계산한 뒤 한꺼번에
적용하고(순서 의존 제거) 다시 예측한다. 대조군은 둘이다. 개수 맞춤은 각 표본에서 motif가 맞은 개수와 같은
수의 무작위 모듈에 같은 개입을 건다. topology 맞춤(`random_matched`)은 여기에 더해 같은 사분면·비슷한
국소 흑색 밀도·같은 데이터 모듈 후보군에서 중심을 골라 위치와 국소 밀도까지 맞춘다.

review_03 2·3절의 지적을 반영해 절차를 두 군데 고쳤다. 첫째, motif 목록을 시드별 train에서만 고르고 같은
시드의 test에서만 절제한다. 옛 절차는 여러 시드의 train을 합쳐 공통 목록을 만든 뒤 그 하나를 모든 시드의
test에 썼는데, 시드 0의 test URL이 시드 1의 train에 들어갈 수 있어 선정과 평가가 분리되지 않았다. 둘째,
무작위 개입은 반복마다 AUROC를 계산한다. 옛 절차는 여러 번 개입한 예측의 로짓을 평균한 뒤 AUROC를
재서, 한 번만 개입한 표적 조건과 비대칭 비교였다. 평균이 무작위 훼손의 영향을 상쇄하므로 무작위 대조의
하락폭이 실제보다 작게 보였다. 그리고 표적 개입과 무작위 개입의 차이 자체(ΔΔAUROC)에 시드 층화 쌍체
CI와 시드별 순열 p를 붙였다. 각각을 원본과 따로 비교하는 것만으로는 두 개입의 차이를 확인할 수 없기
때문이다.

개수 맞춤 무작위는 −0.015 / −0.022 / −0.033, topology 맞춤은 −0.014 / −0.022 / −0.029다. benign motif는
−0.021 / −0.025 / −0.045, 그 무작위 대조는 −0.016 / −0.023 / −0.027이다. 옛 표에서 무작위 대조가
−0.002 ~ −0.008로 거의 움직이지 않았던 것은 로짓 평균이 만든 인공물이었다. 반복마다 AUROC를 재면
무작위 개입도 표적 개입만큼 성능을 떨어뜨린다. 즉 지금까지 "motif 위치를 겨냥했기 때문에 더 떨어졌다"고
읽던 것은 "같은 개수의 모듈을 어디든 뒤집으면 그만큼 떨어진다"로 바뀐다.

로짓의 방향성은 남아 있다. phishing motif를 지우면 phishing 표본의 로짓이 v2 −0.66, v4 −0.82로
내려가고, benign motif를 지우면 benign 표본의 로짓이 +1.19 / +1.16 / +0.80으로 올라가 phishing 쪽으로
밀린다. 같은 개수의 무작위 개입에서는 이 분리가 훨씬 약하다. 다만 로짓 이동은 순위 지표인 AUROC와 다른
양이고 ΔΔAUROC가 0을 배제하지 못하는 이상 이것만으로 인과 기여를 주장하지 않는다. 로짓 방향성은
"개입이 클래스별로 다르게 작용한다"는 기술 통계로만 읽는다.

시드 간 motif 목록도 그리 안정적이지 않다. 시드별 train에서 고른 상위 목록의 Jaccard 평균이 v2 0.507,
v3 0.555, v4 0.411이다. 모든 시드에 공통으로 오른 motif는 6 / 5 / 2개(합집합 21 / 16 / 19개)다. 옛 문서의
"시드 간 안정 motif"라는 표현은 시드 통합 선정이 만든 것이므로 쓰지 않는다.

RQ3 앞부분의 후반, "그 motif가 CNN 판단의 원인인가"의 답은 **지지되지 않음**이다. 7절이 보인
"클래스와 연관된 국소 패치 빈도 분포가 존재한다"는 여전히 유효하지만, 그 분포를 구성하는 특정 motif
위치를 겨냥한 개입이 무작위 개입보다 더 큰 손상을 낸다는 증거는 없다. 이 반전 자체가 결과다 — 대조군을
어떻게 계산하느냐가 인과 주장의 성패를 갈랐고, 옛 결론은 대조군 쪽의 계산 방식에서 나왔다.

한계도 남는다. 개입된 격자는 더 이상 유효한 QR이 아니다. RS 오류정정 덕에 실제 스캐너는 여전히
디코딩할 수 있겠지만, 이것은 모델 입력에 가한 개입이지 실제 QR 변형이 아니다. 그리고 ΔΔ의 CI가 0을
포함한다는 것은 "차이가 없다"가 아니라 이 표본과 이 개입 설계로는 차이를 검출하지 못했다는 뜻이다.
v4는 시드 간 SD가 0.023 ~ 0.027로 커서 특히 검정력이 약하다.

## 5-B. 어휘 프로브 (D)

SmallCNN의 GAP 이후 128차원 임베딩(global average pooling 출력)을 얼리고 그 위에 선형 프로브를 얹어 URL 어휘 특징을 예측한다. 목표는
빈도 상위 char 3-gram 존재 여부, 키워드(`login`, `http`, `.html` 등) 존재 여부, 숫자 비율·점 개수·하이픈
유무 같은 구조 특징, 경로 관련 특징이다. 기준선은 두 개다. 그룹 단위로 목표를 갈아끼운 셔플과,
같은 구조의 미학습(무작위 초기화) CNN 임베딩이다.

review_03 6절의 지적대로 판정을 세 질문으로 분리했다. ① 접근 가능한가(`accessible`): 학습 표현
프로브가 셔플 기준선을 CI 수준에서 넘는가. ② 학습이 접근성을 높였는가(`learned_gain`): 미학습 CNN
기준선까지 넘는가. ③ 그 정보가 실제 분류 결정에 쓰이는가(`used_in_decision`): 동결 표현 위의 선형
프로브로는 측정할 수 없다. 프로브는 표현을 읽을 뿐 결정 경로에 개입하지 않는다. 옛 문서의
"유의(significant)"는 ①과 ②를 한 번에 요구한 ③이 아닌 ②쪽 판정이었다.

아래 수치는 재실행에서 나온 시드별 정확 판정이다. 옛 문서의 ① 수치(v2 45/91 등)는 시드 평균 CI로

해석은 이렇게 정리한다. 사용한 선형 프로브와 판정 기준으로는 임베딩에서 URL 어휘가 선형으로 읽힌다는
증거도, 학습이 그 접근성을 높였다는 증거도 확보하지 못했다. 확인된 것은 경로 구조 특징 두 개뿐이며,
이는 10절이 보인 경로 shortcut과 같은 축을 가리킨다. "CNN이 URL 어휘 신호를 복원한다"는 강한 주장은 이
결과로 지지되지 않지만, "복원이 기각됐다"고 쓰는 것도 과하다. RQ2는 "CNN은 공간 배치를 이용해 URL 유래
내용·순서 신호에 접근하며, 그 접근이 어휘 수준에서 선형으로 읽히는지는 현재 프로브로 확정할 수 없다"로
쓴다. 논문 표현도 recover가 아니라 exploit / access가 맞다.

③ 그 정보가 실제 분류 결정에 쓰이는지는 이 실험이 답하지 않는다. 답하려면 표현에 개입해 예측이
어떻게 변하는지 보는 설계가 필요하다.

프로브가 통과하지 못했다고 해서 정보가 없다는 뜻이 아니다. 비선형 프로브나 문자 시퀀스
디코더를 붙이면 결과가 달라질 수 있고, 그 실험은 아직 하지 않았다.

정식 p값이라는 전제를 대신 세워 주지 않는다.

같은 test 행을 공유하는 쌍체 가설 H1·H4에는 그룹 단위 교환 클러스터 순열 검정의 정식 p값을 함께 싣는다.
여섯 칸 모두 <0.001로, 2,000회 순열에서 관측된 Δ보다 큰 값이 한 번도 나오지 않았다는 뜻이다. 이 자리에서는
pseudo-p가 아니라 순열 p가 정식 p값이다. H2는 참조 기준의 예측이 모델과 다른 절차에서 나와 그룹 단위 교환이
성립하지 않고, H3은 애초에 표본 집합이 달라 쌍체가 아니므로 순열 p를 내지 않는다.

추정치와 CI는 표 본체와 같은 시드 층화 클러스터 부트스트랩에서 나온다. pseudo-p의 해상도는 부트스트랩
반복 2,000회에 묶여 있어(최소 달성 가능 p는 약 0.001) Holm 보정 후 값이 세 가설 모두 0.012로 같게
찍힌다. 이 값은 "효과 크기가 같다"가 아니라 "부트스트랩 해상도의 바닥에 닿았다"로 읽는다.

H1(CNN > 라벨 셔플 바닥, +0.299 ~ +0.374), H2(참조 기준 > CNN, +0.097 ~ +0.187), H4(정상 배치 >
shuffle-pos, +0.107 ~ +0.149)는 세 층 모두에서 CI가 0을 넉넉히 배제한다. Holm 보정 후에도 기각이다.
H3(L-none > L-exact)는 세 층 모두 추정치가 +0.005 / +0.002 / +0.024로 작고 CI가 0을 포함해 비기각이다.
세 층 모두 부호는 양(+)이며 4-1의 시드 평균 차이와 방향이 일치한다.

H3은 애초에 두 조건의 표본 집합이 달라 쌍체 비교가 성립하지 않으므로(4-1, 6-4) 비기각을
"길이 아티팩트가 없다"의 증거로 쓰지 않고, 인과 절제에 더 가까운 `PAD-rand` 쪽을 근거로 삼는다.

## 6. 해석

### 6-1. H1·H2 — 디코딩 없이 URL 유래 내용·순서 신호에 접근한다

길이·버전·패딩 경계를 모두 통제한 주 조건에서 CNN은 v2 0.872, v3 0.814, v4 0.805를 냈다. 같은 층의
라벨 셔플 바닥은 0.498 ~ 0.508, 디코딩 텍스트 참조 기준(char n-gram LR)은 0.969 ~ 0.992다. 갭은
0.097 ~ 0.187로, 바닥에서 참조 기준까지의 거리 중 적잖은 부분을 CNN이 메운 셈이다. 디코딩 없이 QR 모듈
배치만 보고도 URL 유래 내용·순서 신호(URL-derived content/order signal)의 큰 몫을 접근·활용(exploit)한다는 것,
이것이 이 실험의 1차 결론이다. 문자나 n-gram을 실제로 복원(recover)했다는 주장은 쓰지 않는다. 5-B의 프로브와 판정 기준으로는
복원 증거를 확보하지 못했다. 참조 기준 역시 천장이 아니라 강한
텍스트 베이스라인이므로, 갭의 크기는 "남은 정보량"이 아니라 "이 베이스라인과의 거리"로 읽어야 한다.

갭이 층이 올라갈수록 벌어진다는 점(0.097 → 0.158 → 0.187)도 기록해 둔다. URL이 길수록 격자에 담기는
문자 수는 늘지만 CNN이 그것을 읽어내는 난도가 함께 올라간다. v4는 표본이 2,714개로 가장 작아 학습량
부족이 섞여 있을 가능성도 배제할 수 없다.

### 6-2. H4 — 성능은 공간·순서 구조에서 온다 (핵심 결과)

고정 순열로 위치만 흩으면 CNN은 0.872 → 0.765, 0.814 → 0.671, 0.805 → 0.656으로 무너진다(−0.107,
−0.143, −0.149). 같은 순열을 먹인 BitMLP는 0.834 → 0.834, 0.732 → 0.733, 0.690 → 0.706으로 사실상
움직이지 않는다. 고정 순열에 대해 동등한 표현력을 갖는 모델은 안 움직이고 합성곱 모델만 떨어진다. 이 하락은 데이터 파괴가 아니라
공간 구조를 쓰던 모델이 그 구조를 잃은 결과다. 논문의 핵심 그림 F5는 이 2×2다.

MLP의 v4만 +0.016으로 미세하게 올랐는데, 표본이 가장 작은 층의 시드 변동(SD 0.018 ~ 0.019) 범위 안이라
방향성 있는 효과로 읽지 않는다.

### 6-3. CNN이 순서 없는 바이트 분포 이상을 본다

층별로 CNN 0.872/0.814/0.805, BitMLP 0.834/0.732/0.690, byte-hist LR 0.861/0.766/0.771이다. 순서를
완전히 버린 바이트 히스토그램 LR만으로 BitMLP와 같은 수준이 나온다. v2·v4에서는 오히려 더 높다.
그 위에 CNN이 얹는 추가 이득이 있고, 위치를 흩으면 그 이득이 사라진다. 여기까지가 자료가 말하는 것이며
결론은 "원래 배치에 유용한 구조가 있다"까지다.

성능 차이를 신호의 구성 비율로 분해하지 않는다. 옛 문서에는 "문자 조성 + 국소 비트 패턴 + 넓은 범위의
순서 구조"라는 분해 서술이 있었으나 현재 비교로는 세 성분을 가를 수 없다. 근거는 넷이다.

- **BitMLP도 위치 정보를 쓸 수 있다.** 고정 순열 뒤 재학습해도 성능이 유지된다는 것은 가설 공간이
  순열에 대해 동등하다는 뜻이지, 위치를 못 쓴다는 뜻이 아니다.
- **byte-hist LR과 CNN의 점수가 비슷해도** 두 모델이 같은 정보를 쓰는지는 알 수 없다.
- **3×3 패치 LR과 CNN의 차이**에는 수용영역뿐 아니라 비선형성·모델 용량·학습 방식이 함께 섞여 있다.
- **코드워드 셔플은 QR 코드워드의 다중집합을 보존하는 것이지 URL 바이트 히스토그램을 보존하는 것이
  아니다.** 헤더·패딩·오류정정 코드워드가 함께 들어 있으므로 "바이트 조성을 보존한 대조"라고 읽으면
  과하다.

연구 대상의 범위도 좁게 잡는다. 입력은 정규화된 URL 문자열에서 합성한 QR 격자다. 전체 소문자화와
말미 `/` 제거는 경로·쿼리의 의미까지 바꿀 수 있으므로, 여기서 말하는 신호는 그 정규화를 거친 문자열에
대한 것이다.

### 6-4. H3 — 길이 아티팩트는 작다

**단서(중요)**: `L-none`과 `L-exact`는 표본 수·클래스 구성·URL 집합이 함께 달라진다(예: v2는 exact
12,118, none 16,627, 표 T2). 두 조건은 서로 다른 표본으로 학습·평가된다. 그래서 아래 차이는 길이 신호만
추가한 순수한 개입의 효과가 아니라 훈련·평가 집합 구성까지 동시에 바꾼 비교다. 같은 표본 위에서 패딩만
바꾸는 `PAD-rand`가 길이 아티팩트의 인과적 절제에 더 가깝다. 쌍체 부트스트랩도 표본이 대응되지
않아 성립하지 않으므로 이 비교는 비쌍체로만 보고한다. 5-C의 H3 비기각도 같은 이유로 약한 증거다.

`L-none`과 `L-exact`의 차이는 +0.005 / +0.002 / +0.024로 작다. 패딩 주기 패턴을 직접 깨는 `PAD-rand`도
`L-none` 대비 −0.015 / −0.021 / −0.030에 그친다.
길이 단독 LR은 통제를 완전히 푼 `L-none`에서조차 0.543 / 0.544 / 0.610이다. version LR은 층 안에서
버전이 고정이므로 정의상 0.500이다.

해석은 이렇다. 버전 층화와 URL 정규화가 이전 실험의 누출 대부분을 이미 제거했고, 그 위에 얹은 엄격
길이 매칭이 추가로 걷어내는 몫은 작다. 다만 이 통제가 한 일은 길이 주변분포를 클래스 간 일치시킨
것이다. 길이가 다른 특징과 상호작용해 만드는 효과까지 없앤 것은 아니다. 결론의 방향은 "길이 통제를 해도 성능이 유지된다"이지 "길이가
성능의 원천이었다"가 아니다. 다만 v4는 차이가 0.024로 다른 두 층보다 크다. `L-none`의 v4는 클래스 비가
1,404 대 2,526으로 크게 기울어 있어(표 T2) 이 층에 한해 잔여 아티팩트를 완전히 배제하지는 않는다.

### 6-5. 정규화가 성능의 5 ~ 9%p를 좌우한다

`raw`(정규화 해제)는 `norm`보다 +0.049 / +0.060 / +0.087 높다. 선행 `www.`와 대소문자만으로 성능이
5 ~ 9%p 움직인다. 초기 실험의 수치는 지표와 조건이 달라 직접 비교하지 않지만, 표면 정규화가 걷어내는 몫이 이만큼이라는 사실 자체는 기록해 둔다. 두 조건은
각각 독립적으로 dedup되어 표본 구성이 다르므로(raw v3는 11,594, norm v3는 9,178) 절대값 비교보다
"정규화가 손대는 표면 신호의 크기"로 읽어야 한다. 주 결과를 `norm`으로 잡은 이유가 이것이다.

### 6-6. 마스크

mask-auto는 −0.124 / −0.135 / −0.130으로 크게 떨어진다. 반면 mask-off는 mask-fixed와 사실상 동일하다
(−0.001 / −0.011 / +0.011). maskindex LR은 0.524 / 0.486 / 0.517로 우연 수준이다.

세 결과를 합치면 원인이 특정된다. 마스크 인덱스 자체는 라벨의 프록시가 아니다. 문제는 자동 마스크 선택이
같은 URL을 8가지 XOR 패턴 중 하나로 보낸다는 데 있다. 동일한 데이터가 8개의 서로 다른 시각 사상으로
갈라지고, 그만큼 학습이 어려워진다. 마스크를 아예 벗겨도 고정 마스크와 성능이 같다는 사실이 이를 뒷받침한다.
CNN이 배우는 것은 마스크 패턴이 아니라 그 아래 코드워드 배치다.

### 6-7. 기능 패턴, path+, EC-M

- **feat-all vs data_only**: +0.001 / −0.012 / +0.008. 차이 없다. 기능 패턴(파인더·타이밍·정렬)은 층 안에서
  상수 입력이므로 예상대로 정보를 더하지 않는다. Grad-CAM enrichment가 function 영역에서 0.49 ~ 0.66으로
  1보다 작은 것(5절)도 같은 방향이다.
- **path+**: v2에서 0.727로 뚜렷이 낮아지지만(주 조건 0.872) 라벨 셔플 바닥보다는 한참 위다. v3 0.766,
  v4 0.822로 층이 올라갈수록 회복한다. 이 부분집합은 참조 기준 자체도 v2에서 0.914로 낮아지므로
  (주 조건 0.969) 난도가 올라간 문제를 풀고 있는 것이지 신호가 사라진 것이 아니다.
- **EC-M**: v3에서 0.847. 다만 EC 레벨을 바꾸면 같은 URL이 다른 용량·다른 층으로 이동해 표본 구성이
  달라진다(n 10,482 대 9,178, 참조 기준 0.961 대 0.972). 주 결과와 직접 비교할 수 없고 강건성 확인으로만
  쓴다.

## 7. Bag-of-QR-patches (RQ3 직접 검정)

데이터 모듈 위를 stride 1 sliding window로 훑어 2×2·3×3 이진 패치의 출현 빈도 히스토그램을 만들고 그 히스토그램만으로 LR을 돌린다. 창 전체가 데이터 모듈인 경우만 세고, split은 주 조건의 것을 같은 시드로 재현하므로 CNN 실험과 정확히 같은 train/val/test를 쓴다. 모델을 학습하지 않으니 CPU에서 층당 수 분이면 끝난다. 셀은 `AUROC [시드 층화 그룹 클러스터 부트스트랩 95% CI]`로, CNN 표(2 ~ 4절)와 같은 estimator다.

표에는 within-QR 셔플 null 두 판이 함께 들어 있다. 7절의 결과를 국소 공간 의존성으로 올려 쓰려면 조성 차이만으로 재현되지 않는다는 것을 보여야 하기 때문이다. 같은 split·같은 5시드에서 QR마다 데이터 모듈의 0/1 개수를 그대로 보존한 채 위치만 섞었다. 모듈 셔플은 데이터 모듈 전체에 걸쳐 위치를 무작위로 섞어 marginal bit composition만 남긴다. 코드워드 셔플은 코드워드(8모듈) 경계를 유지한 채 코드워드 단위로만 섞어 바이트 조성까지 보존한다. 후자가 더 엄격한 null이다.

읽는 방향은 분명하다. 모듈 위치를 섞으면 세 층 모두 0.498 ~ 0.510으로 라벨 셔플 바닥(0.488 ~ 0.530)과 구분되지 않는다. 3×3 패치 빈도의 신호는 marginal bit composition에서 오는 것이 아니다. 더 엄격한 코드워드 셔플에서도 0.539 ~ 0.555에 머문다. 바이트 조성을 완전히 보존해도 원본 0.707 ~ 0.740의 절반 남짓밖에 복구되지 않는다는 뜻이므로, 바이트 조성으로 설명되지 않는 국소 공간 의존성이 남는다. 원본과 코드워드 셔플의 간격(v2 0.193, v3 0.168, v4 0.160)이 그 몫이다. 두 셔플의 CI가 원본 CI와 겹치지 않으므로 층별로 일관된 분리다.

motif 오즈비는 train에서만 계산하고 부호가 held-out test에서도 유지되는지를 따로 본다. 상위 목록에 오르려면 5시드 부호 일치, 두 클래스 중 한쪽에서 train QR의 1% 이상 등장, 풀링 CI가 0 배제, 비포화를 모두 만족해야 한다. CI는 5시드 train을 (시드, 행)으로 풀링해 부트스트랩 500회로 한 번 만든다. 아래는 층별 상위 phishing motif 세 개다(비트는 창을 row-major로 읽은 것).

### 해석

여기서 지지되는 것은 class-associated local patch-frequency distribution의 존재다. within-QR 셔플 null 두 판을 모두 통과했으므로 marginal bit/byte composition으로 설명되지 않는 국소 공간 의존성까지 올려 쓸 수 있다. 3×3 히스토그램 LR은 세 층에서 0.707 ~ 0.740으로 라벨 셔플 바닥(0.488 ~ 0.530)을 뚜렷이 넘고, 조성만 보존한 셔플은 바닥으로 무너진다. "피싱 QR에 더 자주 나타나는 국소 패치가 있는가"라는 질문의 답은 그렇다다. 다만 개별 motif의 효과는 log OR 0.35 ~ 0.49, 오즈비로 1.4 ~ 1.6 수준이고 존재율 차이도 몇 %p에 그친다. 특정 motif 하나를 "피싱 QR의 서명"이라고 부를 크기가 아니다. 2×2는 0.526 ~ 0.573으로 거의 바닥에 붙는다. 창이 넓어져야 신호가 잡힌다.

motif의 위치가 기여하는 몫은 작다. 전역 히스토그램에 2×2 사분면 넷을 덧붙인 spatial pyramid는 v2에서 0.740 → 0.814로 올라가지만 v3는 0.707 → 0.712, v4는 0.715 → 0.743에 그친다. 차원을 512에서 2,560으로 늘린 대가치고는 v3·v4의 이득이 없다시피 하다. v2에서만 크게 오른 것도 격자가 작아(창 219개) 사분면 분할이 상대적으로 굵은 위치 정보를 준 결과로 읽는 편이 안전하다. 지금 자료로는 motif의 절대 위치가 판별에 중요하다고 말하기 어렵다.

CNN과의 갭은 긴 범위 구조에서 온다. 3×3 히스토그램은 v2 0.740, v3 0.707, v4 0.715인데 CNN은 0.872 / 0.814 / 0.805다. 순서를 완전히 버린 byte-hist LR(0.861 / 0.766 / 0.771)조차 3×3 히스토그램보다 높다. 3×3 창은 코드워드 하나(8모듈)도 온전히 담지 못하는 크기라 바이트 수준의 분포조차 제대로 잡지 못한다. 6-2에서 위치 셔플이 CNN을 0.11 ~ 0.15 떨어뜨린 것과 합쳐 보면, CNN이 쓰는 공간 구조는 3×3 국소 패턴의 빈도가 아니라 그보다 넓은 범위의 배치·순서다.

### C 결과와의 연결

여기서 뽑은 상위 motif가 CNN 판단의 원인인지는 5-A의 절제가 답한다. 개정된 절차에서 나온 답은
**지지되지 않음**이다. 표적 개입의 ΔAUROC(−0.014 ~ −0.045)가 개수·위치·밀도를 맞춘 무작위 개입
(−0.014 ~ −0.033)과 같은 크기다. 두 개입의 차이 ΔΔAUROC는 CI가 0을 포함하거나 경계에 걸린다. 옛
문서가 "원인이기는 하되 작은 몫"이라고 적었던 것은 무작위 대조의 로짓을 평균한 뒤 AUROC를 잰 데서 나온
인공물이었다. 따라서 7절이 지지하는 것은 클래스와 연관된 국소 패치 빈도 분포의 존재까지이고 그
분포를 구성하는 특정 motif 위치가 CNN 결정의 원인이라는 데까지는 가지 않는다. RQ3의 앞부분은 절반만
답한 셈이다. 뒷부분, 새 도메인·새 데이터셋에서의 재현성은 10절이 답한다.

## 8. 한계

1. **benign이 Alexa 계열 상위 사이트에 치우쳐 있다.** WebPhish의 ham은 인기 도메인 목록에서 왔고
   phishing은 신고 기반이다. "피싱 대 정상"이 아니라 "신고된 URL 대 인기 URL"을 풀고 있을 여지가 남는다.
   6-5의 정규화 민감도(선행 `www.`·대소문자로 5 ~ 9%p)가 이 편향의 한 단면이다. 외부 세트에서 Tranco
   조인을 끈 unranked Common Crawl benign이 primary와 거의 같은 결과를 준 것(10절)이 이 축의 크기를
   위에서 한 번 제한해 준다. 다만 경로 편향은 외부 세트로도 통제되지 않는다 — 두 데이터셋 모두
   benign 쪽 경로 보유율이 높고 부호가 같다(10절). 이 축은 `path_lr` 기준선과 길이+경로 동시 매칭
   cohort로 분리했다. 그 뒤 남는 전이 신호는 0.649 / 0.639 / 0.677이다(10절).
2. **v5+ 폐기로 주장 범위가 좁다.** 결론은 URL 18 ~ 78바이트, QR v2 ~ v4 구간에 한정된다. 긴 URL 구간은
   엄격 길이 매칭 후 클래스당 266개만 남아 검정력이 없다. 외부 세트에서는 v5plus가 F-b로 살아났지만
   WebPhish 쪽 참조가 없어 하락폭을 잴 수 없다(10절).
3. **F-c(역방향 전이)와 F-d(혼합 학습)를 실행하지 않았다.** 실행 인자가 `modes=("a","b")`였다. 따라서
   "어느 쪽 신호가 더 일반적인가"라는 비대칭 질문과 "두 도메인 공통 신호가 있는가"는 답하지 못했다.
   F-a의 하락이 WebPhish 특이성 때문인지 외부 세트 특이성 때문인지 가르는 데 F-c가 필요하다.
4. **외부 phishing의 신선도가 세트마다 다르다.** primary인 OpenPhish는 수집 시점 기준 최근 90일이지만
   secondary인 Phishing.Database `phishing-links-ACTIVE.txt`의 마지막 갱신은 2025-12-22이라 역사적
   아카이브다. "active phishing"이라는 표현을 쓰면 안 된다.
5. **외부 benign의 라벨 오염을 실측하지 않았다.** 수동 검토를 하지 않아 `contamination_estimate.p_hat`이
   null이다. 피싱 피드 eTLD+1 제거와 호스팅 블록리스트만 걸었고 VirusTotal·Safe Browsing 검사는 없다.
   오염은 일반적으로 전이 성능을 감쇠시키는 방향으로 예상되지만 라벨 잡음이 systematic하면 단조성이
   보장되지 않는다.
6. **`L-none` v4의 클래스 불균형**(1,404 대 2,526)이 6-4의 잔여 해석을 제한한다.
7. **절제 개입이 규격을 벗어난다.** `PAD-rand`와 5-A의 motif 표적 중심 비트 개입 모두 유효한 QR을 만들지
   않는다. 모델 입력에 가한 개입으로서는 유효하지만 실제 QR 변형으로 읽으면 안 된다.
8. **프로브의 음성 결과는 선형 프로브에 한정된다.** 비선형 프로브나 문자 시퀀스 디코더는 시도하지 않았다.
9. **G의 검정력이 빠듯하다.** 고정 T에서 A의 train에 형제를 실제로 보유한 행이 v2 38 / v3 35 / v4 15개다.
   나머지 행은 애초에 누출 기회가 없으므로 전체 ΔAUROC가 구조적으로 희석된다. v4는 T 자체가 378행이라
   특히 약하다. 11절이 보인 것은 전체 T에서 상승을 SESOI 0.02 아래로 한정했다는 데까지이며, 누출 기회가
   있는 부집합에서는 검출도 배제도 하지 못했다.
10. **전이 판정이 cohort 정의에 민감하다.** 같은 데이터에서 길이만 맞추면 0.744 / 0.702 / 0.693이다.
    경로까지 맞추면 0.649 / 0.639 / 0.677이다. 어느 쪽을 주 판정으로 삼느냐가 결론의 크기를 바꾼다.
    이 문서는 경로까지 맞춘 쪽을 주 판정으로 사전에 정했고, 길이만 맞춘 쪽은 서술용으로만 남긴다.
11. **motif 절제의 음성 결과는 검정력의 한계와 구분되지 않는다.** 5-A의 ΔΔ CI가 0을 포함한다는 것은
    차이가 없다는 뜻이 아니라 이 표본과 이 개입 설계로 차이를 검출하지 못했다는 뜻이다. v4는 시드 간
    SD가 0.023 ~ 0.027로 특히 크다.
12. **결론 두 개를 자체 정정했다.** motif의 인과 기여(5-A)와 어휘 정보의 선형 접근성(5-B)은 이전 판본에서
    지지된다고 적었으나, 대조군 계산 방식과 시드 통합 방식을 고치자 사라졌다. 남은 결론들도 같은 종류의
    절차 의존성을 가질 수 있다.

## 9. 다음 단계

1. **논문 초안** (`docs/REPORT.md`가 뼈대): 참조 기준/바닥/본실험 3층 구조로 서술한다. F5(shuffle-pos 2×2)를
   핵심 그림으로, 7절의 within-QR null을 국소 구조의 증거로, 10절의 길이+경로 매칭 전이 표를 일반화 한계의
   근거로 배치한다. claim은 recover가 아니라 exploit으로 쓰고 "보편적 시각 signature"도 "특정 motif의 인과
   기여"도 쓰지 않는다. 5-A와 5-B의 자체 정정 과정을 방법론 절에 그대로 싣는다.
2. **그림 F2 ~ F8 생성**: 집계는 모두 끝났고 남은 것은 플롯이다.
3. **선택: F-c(역방향 전이)와 F-d(혼합 학습)**. F-c는 F-b 체크포인트가 이미 있으므로 추론만으로 끝난다.
   전이 비대칭을 재는 가장 싼 실험이고 5.2의 세 가설을 가르는 유일한 장치다.
4. **선택: 비선형 프로브와 문자 시퀀스 디코더**. 5-B의 음성 결과가 선형에 한정된다는 단서를 걷어내려면
   이 둘 중 하나가 필요하다. 여기서 문자 복원율이 나오면 그때 비로소 RQ2를 "복원"으로 올릴 수 있다.
5. **선택: 표현 개입 설계**. 프로브 ③(그 정보가 실제 결정에 쓰이는가)은 동결 표현 위의 선형 프로브로
   답할 수 없다. 임베딩 방향을 지우고 예측 변화를 보는 설계가 필요하다.

**하지 않기로 한 것.** 외부 세트에서의 motif 인과 절제는 필요가 없어졌다. 내부에서 표적 개입과 무작위
개입이 구분되지 않으므로, 외부에서 같은 절제를 돌려도 답할 질문이 남지 않는다.

## 10. 외부 검증 (F)

WebPhish로 학습한 모델을 다른 데이터셋에 그대로 걸어 RQ3의 뒷부분에 답한다. primary 세트는 OpenPhish
`public_feed` 최근 90일(고유 URL 43,990건)과 Common Crawl `CC-MAIN-2026-34` × Tranco 조인 benign이다.
secondary는 Phishing.Database `phishing-links-ACTIVE.txt`와 같은 benign이다. 외부에도 WebPhish와 동일한
순서(층 필터 → eTLD+1 그룹 분할 → split별 엄격 길이 매칭)를 적용한다. 임계값은 WebPhish val에서 고른 값을
그대로 쓴다. F-a는 고정 외부 cohort(시드 0의 절차로 한 번 만들어 얼린 행 집합에 시드 0 ~ 4의
다섯 모델을 모두 평가)로 보고한다. 시드별 cohort는 F-b와의 쌍체 비교용 보조다. 바닥선은 라벨 셔플이 아니라
외부 라벨을 그룹 단위로 순열해 얻은 AUROC 분포의 97.5 백분위이며, 재실행에서 설계 목표대로 2,000회를
채웠다. 그룹 순열이 양성 총수를 보존하지 않는 문제를 대조하기 위해 행 단위 순열 바닥선도 함께 싣는다
(표의 `행순열 바닥선` 열, 0.503 ~ 0.520). 기준선은 CNN과 같은 5시드·같은 평가 행에서 다시 계산해 쌍체
ΔAUROC와 CI를 붙였다.

출처 편향의 방향 (2026-09-09 정정). 이 절의 옛 서술은 "WebPhish는 benign이 짧고 경로가 없는데
외부는 그 방향이 뒤집혔다"였다. 틀렸다. `reports/external/bias_stages.json`의 단계별 통계를 보면
`path_depth>=1` 비율이 원본에서 WebPhish benign 99.7% 대 phishing 69.8%, 외부 benign 93.9% 대
phishing 46.0%다. v2 길이 매칭 후에도 99.75% / 44.3% 대 86.8% / 33.7%다. 두 데이터셋 모두 benign 쪽
경로 보유율이 훨씬 높으며 부호가 전 층에서 같다. WebPhish benign은 맨 도메인 코퍼스가 아니라 경로를
가진 심층 페이지 코퍼스다. 라벨 매핑(`spam`→phishing, `ham`→benign)은 재확인했고 문제가 없다.

따라서 외부 세트는 편향을 뒤집는 stress test가 아니라 같은 방향의 편향을 공유하는 세트다. 게이트는
차단이 아니라 플래그 방식으로 재설계했고(`docs/EXTERNAL_VALIDATION_DESIGN.md` 6.1절), 전이 성능 중 경로
모양이 설명하는 몫을 두 장치로 떼어냈다. 하나는 경로 유무·깊이·구분자 비율만 쓰는 path-shape LR
기준선이고 다른 하나는 길이와 경로를 함께 맞춘 `a_fixed_lenpath` cohort다. 후자가 주 판정이고
길이만 맞춘 cohort는 `reported_unmatched_path`로 표시해 서술용으로만 남긴다.

### 해석

길이만 맞춘 cohort의 점수에는 경로 shortcut이 섞여 있다. primary에서 CNN은 0.744 / 0.702 / 0.693인데,
같은 cohort에서 경로 모양만 쓰는 path-shape LR이 0.780 / 0.638 / 0.602다. v2에서는 이 기준선이 CNN을
넘고(쌍체 Δ = CNN − path −0.036 [−0.081, +0.016]) v3·v4에서도 CNN과 같은 구간이다. 경로 유무·깊이·구분자
비율 세 가지만으로 전이 점수의 대부분이 설명된다는 뜻이므로, 이 cohort의 숫자를 "QR 공간 신호의 전이"로
읽으면 안 된다. 세 층 모두 `reported_unmatched_path`로 표시했다.

경로까지 맞추면 신호가 줄되 바닥선 위에 남는다. `a_fixed_lenpath` cohort에서 CNN은 0.649 [0.626, 0.670] /
0.639 [0.609, 0.667] / 0.677 [0.639, 0.724]다. 순열 바닥선은 0.530 / 0.537 / 0.558, 행 단위 순열 바닥선은
0.506 / 0.505 / 0.506이다. CI 하한이 세 층 모두 두 바닥선 위다. 같은 cohort에서 path-shape LR은
0.509 / 0.394 / 0.542로 무너진다. CNN 대비 쌍체 Δ는 +0.140 [+0.106, +0.174] / +0.244 [+0.166, +0.312] /
+0.135 [+0.059, +0.259]로 뒤집힌다. 즉 경로 모양을 통제하고 나면 CNN이 그 기준선보다 뚜렷이 낫다.
판정은 v2 `partial_collapse`, v3·v4 `reproduced_weak`다. WebPhish 내부 성능(0.872 / 0.814 / 0.805) 대비
하락폭은 −0.223 / −0.175 / −0.128로 길이만 맞췄을 때보다 커졌다.

텍스트 기준선이 CNN보다 잘 전이된다. 이제 같은 5시드·같은 평가 행에서 계산한 쌍체 Δ로 말할 수 있다.
`a_fixed_lenpath` primary에서 char n-gram LR은 0.714 / 0.834 / 0.796이다. Δ(CNN − char n-gram)는
−0.065 [−0.087, −0.042] / −0.195 [−0.236, −0.153] / −0.119 [−0.190, −0.057]로 세 층 모두 CI가 0을 배제한다.
다른 외부 세트까지 합치면 이 Δ는 −0.09 ~ −0.24 구간에 흩어진다. 반면 byte-hist LR과의 Δ는
+0.005 [−0.028, +0.037] / +0.044 [−0.012, +0.098] / −0.015 [−0.076, +0.035]로 세 층 모두 CI가 0을 포함한다.
경로와 길이를 맞추고 나면 CNN과 바이트 조성 기준선은 구분되지 않고, 문자 n-gram만 확실히 앞선다.
motif-hist LR(3×3)은 0.576 / 0.559 / 0.591로 가장 낮고 CNN이 +0.073 ~ +0.086 앞선다. 공간적일수록 덜
전이된다는 방향은 유지된다.

신호가 없어서가 아니라 전이가 안 되는 것이다. 같은 외부 데이터로 학습한 F-b는 0.892 / 0.918 / 0.868로
WebPhish 내부와 같거나 높다. 외부 세트 자체에는 학습 가능한 QR 신호가 충분히 있다는 뜻이므로 F-a의
하락은 도메인 시프트로 읽는다. 다만 F-b v2는 path-shape LR이 0.849로 CNN 0.892에 근접해 경로 shortcut
플래그가 걸렸고 판정이 `descriptive_only`다. v3·v4는 `reproduced_strong`, v5plus는 WebPhish 쪽 참조가
없어 `reproduced_unknown_reference`다.

민감도와 강건성 조건도 같은 방향이다. 정제 절제 두 조건(피싱 도메인 유지, 호스팅 블록리스트 미적용)은
길이 매칭 cohort에서 primary와 소수점 셋째 자리까지 사실상 같다. 후자는 primary benign에서 한 건도
제거하지 않는 no-op임이 수집 단계에서 확인됐으므로, 절제로서의 정보량이 없다는 사실 자체가 결과다.
Tranco 조인을 끈 unranked Common Crawl benign은 길이+경로 매칭에서 0.636 / 0.604 / 0.666으로 primary와
같은 구간이다. secondary(Phishing.Database)는 길이+경로 매칭에서 0.652 / 0.700 / 0.760이다. v4만
`reproduced_strong`, v3 `reproduced_weak`, v2 `partial_collapse`다. 인기 도메인 confound와 benign 정제
낙관 편향은 어느 조건에서도 관측되지 않는다.

개별 motif는 대체로 재현되지 않는다. primary 고정 cohort에서 512종 log OR의 Spearman ρ가
0.228 [0.113, 0.256] / 0.066 [0.019, 0.109] / 0.073 [−0.018, 0.142]다. CI 하한이 0.2를 넘는 층이 하나도
없다. 상위 20 부호 일치율은 0.850 / 0.500 / 0.650으로 v2만 귀무(0.5)를 배제한다. 상위 20 Jaccard는
0.026 / 0.053 / 0.000으로 귀무 상한 0.081 이하다. 판정은 v2 `partial`, v3·v4 `failed`다. secondary는 v2만
`reproduced`이고 v3·v4는 `partial`이다. 전 세트를 합치면 ρ 0.03 ~ 0.32, 부호 일치율 0.45 ~ 0.90 구간에
흩어진다. 여기 쓰인 WebPhish 쪽 motif 목록도 시드별 선정 절차에서 다시 뽑은 것이다.

세 결과를 합치면 방향은 하나다. 출처와 구조의 차이(길이, 경로 모양)를 통제한 뒤 남는 전이 신호는 작지만
순열 바닥선을 넘는다. 그리고 그 신호는 텍스트 기준선만큼 잘 전이되지 않으며, 개별 motif의 정체는
데이터셋 특이적이다. RQ3의 뒷부분의 답은 "약하게 그렇다"이고 "피싱 QR에 보편적인 시각 signature가
있다"는 문장은 이 결과로 지지되지 않는다.

## 11. 템플릿 누출 (G)

eTLD+1만 격리한 분할이 phishing kit·경로 템플릿 수준의 누출을 놓치고 있는지 본다. 설계를 한 번 갈아엎었다.
1차 분할과 템플릿 분할을 각각 돌려 비쌍체로 빼던 옛 방식은 1차 test 행의 86 ~ 88%가 교체됐고 test cohort
Jaccard도 0.06 ~ 0.10이었다. 그래서 효과를 분리할 수 없어 폐기했다. 지금은 URL 토큰·경로 템플릿의 MinHash 클러스터와
eTLD+1을 union-find로 합친 성분 단위로 캠페인 test 집합 T를 하나 고정한다. 그 위에서 학습 조건만 다른 두
모델을 쌍체 비교한다. Model A는 eTLD+1만 격리(T와 같은 캠페인의 다른 도메인, 곧 형제 행을 train에 허용),
Model B는 eTLD+1과 템플릿까지 격리한다. 주 지표는 형제를 전부 둔 채 비형제를 덜어 `|train| = |train_B|`로 맞춘
`A_sm`과 B의 차이 ΔAUROC = A_sm − B다. 세 모델이 같은 T를 평가하므로 전부 쌍체다.

- 누출 대조 표본 수 (v4): 시드당 평균 15행

### 해석

판정 규칙을 먼저 고쳤다. 옛 규칙은 "쌍체 CI 하한이 0 이하이면 누출 무시 가능"이었다. 이 규칙은
CI가 `[-0.10, +0.30]`처럼 큰 양의 효과까지 허용해도 같은 판정을 내주므로, 비유의성을 효과 부재로
읽게 만든다. 그래서 SESOI(smallest effect size of interest)를 AUROC 0.02로 사전에 정하고 등가성
형태로 판정한다. CI 상한이 0.02 미만일 때만 `negligible`이고 CI가 0을 포함하되 상한이 0.02 이상이면
`not_detected`. 검출도 배제도 못한 상태다.

주 지표는 세 층 모두 `negligible`이다. ΔAUROC(A_sm − B)가 −0.010 / +0.001 / −0.014다. 쌍체 95% CI
상한은 0.0011 / 0.0145 / 0.0151로 셋 다 SESOI 0.02 아래다. 그룹 단위 교환 클러스터 순열 p도
0.496 / 0.946 / 0.742다. Model B의 AUROC도 0.851 / 0.774 / 0.828로 라벨 셔플 바닥보다 한참 위라 "결론 무효"
칸에는 걸리지 않는다. 여기까지가 이 실험이 보인 것이다. 정의한 템플릿 분리 방식과 평가 집합에서
전체 AUROC 상승을 SESOI 0.02 아래로 한정했다.

누출 기회가 있는 행만 보면 검출도 배제도 못했다. T 표본은 1,688 / 1,273 / 378행인데 그중 A의 train에
형제를 실제로 보유한 행은 시드당 평균 38 / 35 / 15개다. 나머지 행에는 애초에 누출 기회가 없으므로 전체
ΔAUROC는 구조적으로 희석된다. 누출 행만 따로 본 부집합 지표는 +0.017 / +0.064 / +0.028로 부호가 셋 다
양(+)이다. CI 상한이 0.09 ~ 0.16이라 판정은 전부 `not_detected`다. 표본이 수십 행뿐이라 이 부집합에서
`negligible`은 구조적으로 나올 수 없다. phishing kit 암기 가능성을 배제한 것은 아니다. URL 템플릿
클러스터가 실제 공격 캠페인의 완벽한 정답 라벨도 아니다. 이 지표는 표본 구성이 달라 전체 T의 Δ와 크기를
직접 비교해서도 안 된다.

분할 자체는 의도대로 작동했다. B의 train에 T와 템플릿이 겹치는 행은 세 층 모두 0행이고 A에는
44 / 32 / 15행이 있다.

옛 비쌍체 G의 차이는 분해되지 않는다. 옛 방식은 1차 test 행의 86 ~ 88%가 교체된 상태에서 두 조건을
비교했다. 따라서 그때 본 0.08 수준의 격차를 두고 지금 말할 수 있는 것은 옛 비교가 test 교체 효과와
누출 효과를 분리할 수 없었다는 데까지다. "그 차이는 test 교체 효과였다"고 단정하지 않는다.

텍스트 베이스라인의 Δ도 0 근처다. Δ char n-gram LR은 −0.000 / +0.001 / −0.000, Δ byte-hist LR은
+0.002 / +0.000 / +0.001이다. 어휘 수준에서도 템플릿 누출로 얻는 이득은 관측되지 않았다. 크기를 맞추지
않은 보조 지표 `A − B`는 −0.011 / +0.014 / +0.009다. 판정은 v2 `negative`, v3 `detected_minor`,
v4 `not_detected`로 층마다 갈린다. v3에서 CI 하한이 0을 넘는다는 점은 기록해 둔다. 크기를 맞추지
않으면 학습 표본 수 효과가 Δ에 섞이므로 주 지표는 `A_sm`이지만, 보조 지표가 층 하나에서 작은 이득을
검출했다는 사실을 지우지는 않는다.
