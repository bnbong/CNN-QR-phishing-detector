# 실험 결과 - QR 모듈 격자 기반 피싱 URL 분류

설계 스펙은 `docs/EXPERIMENT_DESIGN.md`. 이 문서의 모든 표는 `reports/`의 집계 CSV, JSON에서
`scripts/make_results_tables.py`로 생성했다. 수치를 고칠 일이 있으면 CSV를 고치고 스크립트를 다시 실행한다.

## 0. 연구 질문과 결과 요약

주 실험은 URL 정규화, QR 버전 층화, 분할별 1바이트 길이 매칭, eTLD+1 그룹 분리를 적용했다. SmallCNN의 AUROC는 v2 / v3 / v4 순으로 0.872 / 0.814 / 0.805였다. 별도의 고정 캠페인 평가 집합에서 도메인과 템플릿을 모두 분리한 Model B는 0.851 / 0.774 / 0.828을 기록했다. 두 실험은 평가 집합과 비교 설계가 다르므로 통제를 누적한 단일 결과로 해석하지 않는다.

모든 표본에 동일한 고정 위치 순열을 적용해 재학습하면 CNN의 AUROC는 0.107 / 0.143 / 0.149 낮아졌고 BitMLP의 변화는 작았다. 이는 원래 QR 배치가 해당 CNN의 학습에 유리함을 보여 준다. 3×3 패치 빈도에도 클래스와 연관된 차이가 있었지만, 피싱 관련 motif에 대한 표적 개입은 위치와 밀도를 맞춘 무작위 대조보다 일관되게 큰 손상을 일으키지 않았다. 정상 관련 motif의 v4 결과 등 일부 비교에서는 차이가 확인되므로 모든 개입 효과가 같았다고 일반화하지 않는다.

선형 프로브의 접근성 기준을 통과한 목표는 26/91, 13/114, 1/104였고, 학습 이득 기준까지 통과한 목표는 v2의 경로 유무와 깊이 두 가지였다. 이 수치는 어휘와 구조를 포함한 목표의 통과 수이며, 실제 문자 복원이나 분류 결정에 사용된 정보량을 뜻하지 않는다. 길이와 경로 유무를 함께 맞춘 외부 평가에서 CNN의 AUROC는 0.649 / 0.639 / 0.677이었다. 순열 대조 기준값보다 높았지만 같은 표본에서 평가한 문자 n-gram LR보다 낮았다. 따라서 학습 가능한 판별 신호는 확인했으나, 데이터셋 전반에 통용되는 피싱 고유 패턴이나 특정 motif의 보편적인 인과적 기여를 입증하지는 못했다.

입력은 정규화 URL에서 합성한 2채널 QR 격자다. 촬영 QR의 성능은 평가하지 않았다. 상세 절차 변경 이력은 5-A, 5-B, 10, 11절에 기록했다.

## 1. 실험 요약

- **데이터**: WebPhish(Opara et al., 2024). URL 정규화(소문자화, 선행 `www.` 1회 제거, 말미 `/` 제거) 후 중복, 라벨 충돌 제거. QR 생성 조건은 EC=L, `optimize=0`(단일 8비트 바이트 청크), `mask_pattern=0` 고정. 모델 입력은 PNG가 아니라 `(2, n, n)` 비트 격자(값 채널 + 데이터 모듈 마스크)다.
- **층**: QR 버전 v2/v3/v4가 primary(엄격 길이 매칭 후 클래스당 ≥1,000). v5+는 매칭 후 클래스당  266개만 남아 설계에 명시한 규칙대로 **폐기**했다. 따라서 이 문서의 결론 범위는 URL 길이 18 ~ 78바이트 구간이다.
- **표본 수**(주 조건 `L-exact`): v2 12,118 / v3 9,178 / v4 2,714, 층 안에서 두 클래스 1:1.
- **분할과 통계**: eTLD+1 그룹 그리디 빈패킹 70/15/15, 단일 그룹 5% 상한 다운샘플. 시드 5개(0 ~ 4)를 분할, 서브샘플, 초기화에 함께 걸어 평균과 SD를 낸다. 95% CI는 표본이 아니라 **그룹을 리샘플링하는 시드 층화 클러스터 부트스트랩**이다. 부트스트랩 반복마다 eTLD+1 그룹을 리샘플링하되 AUROC는 시드별로 따로 계산해 평균하므로, 시드 간 점수 척도 차이가 통합 추정치를 끌고 가지 않는다 (`reports/*`의 `pooling: seed_stratified`).
- **누출 진단**: `reports/split_diagnostics.json`의 12개 층 셀 전부에서 split 간 eTLD+1 교집합이 0이다. test 상위 5개 그룹이 차지하는 비중은 18.7 ~ 20.6%다.
- **역매핑 게이트**: 통과(1,584건 검사, 실패 0). 모듈 ↔ 비트 ↔ 코드워드 ↔ URL 바이트 역매핑이 라운드트립으로 검증되지 않으면 학습 자체를 돌리지 않는다.
- **디코딩 텍스트 참조 기준**: 모든 조건, 층에서 CNN AUROC가 char n-gram LR(디코딩 텍스트 참조 기준) 아래였다. 이 참조 기준은 **강한 텍스트 베이스라인**일 뿐 Bayes 최적 분류기가 아니므로 상한선이 아니며, 넘더라도 누출의 증거가 되지 않는다. 따라서 부호 있는 차이(`gap_to_decoded_text` = 참조 - CNN)만 보고하고 누출 판정용 부등식 검사는 두지 않는다. 누출 진단은 라벨 셔플 대조군과 split 진단이 담당한다.
- **하드웨어**: Colab T4 단일 GPU.

## 2. 주 결과 (T3)

주 조건은 `norm`, `L-exact`, `data_only`(기능 패턴 제거), `mask-fixed`, SmallCNN이다. 셀은 `AUROC 5시드 평균 [시드 층화 클러스터 부트스트랩 95% CI]`.

| 모델 / 기준선 | v2 | v3 | v4 |
|---|---|---|---|
| SmallCNN (주 조건) | 0.872 [0.846, 0.892] | 0.814 [0.773, 0.853] | 0.805 [0.771, 0.837] |
| BitMLP | 0.834 [0.801, 0.862] | 0.732 [0.695, 0.773] | 0.690 [0.649, 0.727] |
| 라벨 셔플 (음성 대조) | 0.498 [0.477, 0.519] | 0.508 [0.489, 0.525] | 0.506 [0.478, 0.540] |
| char n-gram LR (디코딩 텍스트 참조 기준) | 0.969 | 0.972 | 0.992 |
| byte-hist LR | 0.861 | 0.766 | 0.771 |
| length LR | 0.500 | 0.500 | 0.500 |
| version LR | 0.500 | 0.500 | 0.500 |
| 참조 기준 - CNN 갭 | +0.097 | +0.158 | +0.187 |

시드 평균과 시드 간 SD로 읽으면 CNN은 0.872(SD 0.019) / 0.814(SD 0.030) / 0.805(SD 0.010)이다. 라벨 셔플은 0.498(SD 0.012) / 0.508(SD 0.013) / 0.506(SD 0.032)이다. 바닥이 세 층 모두 0.50 근방에 붙는다. 이 음성 대조에서 이상 성능은 관측되지 않았다는 뜻이며 "누출이 없다"는 증명은 아니다. length LR과 version LR은 `L-exact`에서 정확히 0.500인데, 이것은 성능이 아니라 설계가 의도대로 작동했다는 확인이다. 층 안에서 버전이 고정이고 길이 주변분포가 클래스 간 동일하므로 두 변수는 정의상 라벨 정보를 갖지 않는다.

## 3. H4 - 공간 구조 검정

`shuffle-pos`는 모든 표본에 동일한 고정 순열을 걸어 픽셀 값 집합은 그대로 두고 원래의 공간 인접 관계만 바꾼다. 고정 순열은 정보를 보존하는 가역 변환이므로 위치 정보를 없애는 조작이 아니다. BitMLP는 대조군 역할을 한다. 정확히 말하면 MLP 자체가 순열 불변인 것이 아니라, 재학습되는 MLP의 가설 공간이 입력 좌표의 고정 순열에 대해 표현력이 동등하다. 같은 가중치에서 f(Px)=f(x)가 성립한다는 뜻이 아니라, 순열된 입력으로 다시 학습하면 원래와 같은 성능에 도달할 수 있다.

| 조건 | v2 | v3 | v4 |
|---|---|---|---|
| CNN, 원래 배치 | 0.872 [0.846, 0.892] | 0.814 [0.773, 0.853] | 0.805 [0.771, 0.837] |
| CNN, shuffle-pos | 0.765 [0.722, 0.803] | 0.671 [0.641, 0.703] | 0.656 [0.626, 0.689] |
| CNN 차이 | -0.107 | -0.143 | -0.149 |
| MLP, 원래 배치 | 0.834 [0.801, 0.862] | 0.732 [0.695, 0.773] | 0.690 [0.649, 0.727] |
| MLP, shuffle-pos | 0.834 [0.801, 0.863] | 0.733 [0.696, 0.772] | 0.706 [0.666, 0.744] |
| MLP 차이 | +0.000 | +0.001 | +0.016 |

CNN의 하락폭 -0.107 / -0.143 / -0.149는 두 조건의 시드 간 SD(0.010 ~ 0.030, 0.012 ~ 0.021)보다 확연히 크다.

## 5. Grad-CAM (P3, 보조 분석)

절차를 개정했다. 첫 시드의 앞쪽 128표본이 아니라 5시드 × 클래스 균형 무작위 640표본을 쓰고, 타깃도 부호를 붙였다(phishing은 +logit, benign은 -logit). 그래야 benign CAM이 "이 표본에서 phishing 로짓을 올리는 곳"이 아니라 그 표본이 benign으로 판정된 근거를 가리킨다. 해석 대상 조건은
`norm-exact-data_only-off-small_cnn`(언마스킹 격자)이다. 마스크 XOR이 걷힌 상태라야 CAM 질량을 코드워드 종류(kind)에 곧바로 귀속시킬 수 있다.

| CAM 질량 (kind) | v2 | v3 | v4 |
|---|---|---|---|
| char (URL 문자) | 50.6% | 57.3% | 64.6% |
| pad (패딩) | 9.8% | 11.7% | 12.3% |
| ec (오류정정) | 8.7% | 9.7% | 9.0% |
| function (기능 패턴) | 28.2% | 19.6% | 12.7% |
| length_header | 1.7% | 1.0% | 0.7% |
| mode_header | 0.7% | 0.4% | 0.3% |
| remainder | 0.2% | 0.3% | 0.1% |
| char / 데이터 모듈 내 비율 | 70.7% | 71.6% | 74.4% |
| n_samples | 640 | 640 | 640 |

질량 비율만으로는 아무 말도 못 한다. char 영역이 데이터 모듈의 대부분을 차지하므로 질량이 몰리는 것은 당연하다. 필요한 것은 면적으로 정규화한 enrichment(= CAM 질량 분수 / 영역 면적 분수)와 난수 귀인 기준선이다.

- char 영역의 enrichment는 세 층 모두 1보다 높다(1.43 ~ 1.57). v2에서는 header와 pad도 1보다 높으므로 char에만 집중한다고 해석할 수는 없다.
- function은 0.49 ~ 0.66, ec는 0.61 ~ 0.68로 1보다 작다. 옛 절차에서 function 질량이 16 ~ 34%로 나와 "업샘플링 번짐"으로 해석했던 부분인데, 면적으로 나누면 오히려 덜 보는 영역이다. 기능 패턴이 층 안 상수 입력이라 정보를 더하지 않는다는 4-2의 결과와 방향이 맞는다.
- pad는 0.98 ~ 1.13으로 사실상 면적만큼이고 remainder는 0.18 ~ 0.34로 가장 낮다.
- 난수 귀인 기준선은 모든 kind에서 0.99 ~ 1.00이다. 정규화가 의도대로 작동한다는 확인이다.

sanity check도 통과했다. 마지막 블록 가중치를 무작위화한 모델의 CAM과 학습 모델 CAM의 상관은 v2 0.076 / v3 0.021 / v4 -0.067로, 절댓값이 모두 0.08 이하다. 가중치를 망가뜨려도 같은 히트맵이 나오는 전형적인 실패 모드는 아니다.

`char_position_curve`(URL 상대 위치 50구간별 CAM 질량, 클래스별)는 부호 있는 타깃으로 바꾼 뒤 클래스 간 격차가 거의 사라졌다. 구간 평균은 v2 benign 0.405 대 phishing 0.387, v3 0.315 대 0.327, v4 0.348 대 0.245로 방향이 층마다 다르다. 옛 절차에서 "phishing 곡선이 전 구간에서 위"로 보였던 것은 두 클래스 모두에 phishing 로짓을 타깃으로 걸었던 데서 나온 인공물로 본다. 이 곡선에서 클래스 차이를 읽지 않는다.

Grad-CAM은 여기까지가 역할이다. 어느 영역을 보는지 보여주는 기술 통계이고 인과 주장은 다음 절의 절제 결과로만 한다.

## 5-A. 인과 motif 절제 (C)

7절에서 뽑은 층별 상위 motif가 실제로 CNN 판단의 원인인지 본다. 개입의 이름은 motif 표적 중심 비트 개입 (motif-targeted center-bit intervention)이다. 절차는 이렇다. test 표본의 데이터 모듈에서 상위 motif와 일치하는
3×3 창을 찾고 매칭된 3×3 창의 중심 모듈 하나만 뒤집는다. 창 전체를 바꾸는 것이 아니라 창당 모듈 하나를 바꾸는 것이므로 "motif 뒤집기"라는 표현은 쓰지 않는다. 매칭은 원본 격자 한 벌에서 모두 계산한 뒤 한꺼번에 적용하고(순서 의존 제거) 다시 예측한다. 대조군은 둘이다. 개수 맞춤은 각 표본에서 motif가 맞은 개수와 같은 수의 무작위 모듈에 같은 개입을 건다. 위치 및 밀도 맞춤(`random_matched`)은 여기에 더해 같은 사분면, 비슷한 국소 흑색 밀도, 같은 데이터 모듈 후보군에서 중심을 골라 위치와 국소 밀도까지 맞춘다.

review_03 2, 3절의 지적을 반영해 절차를 두 군데 고쳤다. 첫째, motif 목록을 시드별 train에서만 고르고 같은 시드의 test에서만 절제한다. 옛 절차는 여러 시드의 train을 합쳐 공통 목록을 만든 뒤 그 하나를 모든 시드의 test에 썼는데, 시드 0의 test URL이 시드 1의 train에 들어갈 수 있어 선정과 평가가 분리되지 않았다. 둘째, 무작위 개입은 반복마다 AUROC를 계산한다. 옛 절차는 여러 번 개입한 예측의 로짓을 평균한 뒤 AUROC를 재서, 한 번만 개입한 표적 조건과 비대칭 비교였다. 평균이 무작위 훼손의 영향을 상쇄하므로 무작위 대조의 하락폭이 실제보다 작게 보였다. 그리고 표적 개입과 무작위 개입의 차이 자체(ΔΔAUROC)에 시드 층화 쌍체 CI와 시드별 순열 p를 붙였다. 각각을 원본과 따로 비교하는 것만으로는 두 개입의 차이를 확인할 수 없기 때문이다.

## 5-B. 어휘 프로브 (D)

SmallCNN의 GAP 이후 128차원 임베딩(global average pooling 출력)을 고정하고 그 위에 선형 프로브를 얹어 URL 어휘 특징을 예측한다. 목표는 빈도 상위 char 3-gram 존재 여부, 키워드(`login`, `http`, `.html` 등) 존재 여부, 숫자 비율, 점 개수, 하이픈 유무 같은 구조 특징, 경로 관련 특징이다. 기준선은 두 개다. 그룹 단위로 목표를 재배정한 셔플과, 같은 구조의 미학습(무작위 초기화) CNN 임베딩이다.

review_03 6절의 지적대로 판정을 세 질문으로 분리했다. ① 접근 가능한가(`accessible`): 학습 표현 프로브가 셔플 기준선을 CI 수준에서 넘는가. ② 학습이 접근성을 높였는가(`learned_gain`): 미학습 CNN 기준선까지 넘는가. ③ 그 정보가 실제 분류 결정에 쓰이는가(`used_in_decision`): 동결 표현 위의 선형 프로브로는 측정할 수 없다. 프로브는 표현을 읽을 뿐 결정 경로에 개입하지 않는다. 옛 문서의 "유의(significant)"는 셔플 기준선과 미학습 CNN 기준선을 모두 넘는 판정으로, 현재의 ②에 해당한다.

**①의 전 시드 판정을 재집계로 확정했다.** 노트북 [11]을 다시 돌려 시드별 프로브 캐시 (`reports/probes/{cid}/{stratum}/seed{k}.json`)를 복원하고 `recompute_probe_summaries`로 다시 집계했다. 기준은 `exact:seed_cache`이고 시드 평균 CI로 근사한 대목은 없다. 옛 문서의 "접근성 2/91"은 표 생성기가 새 집계 필드를 찾지 못해 세 질문 칸에 옛 `n_significant`를 대신 채운 폴백 오류였고(review_04), 정확값은 v2 26/91, v3 13/114, v4 1/104이다. 옛 판본의 ① 수치(v2 45/91 등)는 시드 평균 CI로 근사한 값이므로 되살리지 않는다.

pseudo-p는 부트스트랩 백분위 CI를 역전시켜 정의한 값이지 영가설 분포에서 나온 정식 p값이 아니다. Holm 보정도 그 값에 건 것이므로 "보정 후에도 유의"라는 표현은 쓰지 않는다. 정식 판정은 위 가설 검정 표를 본다.

판정 규칙은 이렇다. 쌍체 ΔAUROC의 95% 양측 백분위 CI가 0을 배제하는지로 판정하고, p값은 그 CI를 역전시켜 정의한 뒤(CI가 0을 배제하는 가장 작은 alpha) 12개 검정 family에 Holm 보정을 건다. 이 값은 영가설 아래에서 재표집한 정식 귀무분포 p값이 아니다. 그래서 이름을 `bootstrap-tail pseudo-p`로 바꿔 쓰고 명목 유의수준을 정확히 지킨다고 보지 않는다. 본문의 주 결과는 ΔAUROC 추정치와 클러스터 부트스트랩 CI이고 pseudo-p는 정식 가설 검정 표에서 빼 부록 성격의 참고값으로만 둔다. 이름을 바꾼 것만으로 정식 p값의 성질이 생기지는 않으며 Holm 보정도 그 문제를 해결해 주지 않는다. Holm은 여러 p값의 family-wise error를 다룰 뿐, 각 값이 정식 p값이라는 전제를 대신 세워 주지 않는다.

같은 test 행을 공유하는 쌍체 가설 H1, H4는 그룹 단위 교환 클러스터 순열 검정의 정식 p값을 중심으로 보고한다. 여섯 칸 모두 <0.001로, 2,000회 순열에서 관측된 Δ보다 큰 값이 한 번도 나오지 않았다는 뜻이다. 반복 수를 늘리는 것은 몬테카를로 계산 오차를 줄일 뿐 교환 가능성 가정을 검증해 주지 않는다. 이 자리에서는 pseudo-p가 아니라 순열 p가 정식 p값이다. H2는 참조 기준의 예측이 모델과 다른 절차에서 나와 그룹 단위 교환이 성립하지 않고, H3은 애초에 표본 집합이 달라 쌍체가 아니므로 순열 p를 내지 않는다.

추정치와 CI는 표 본체와 같은 시드 층화 클러스터 부트스트랩에서 나온다. 이 CI는 저장된 모델들의 예측에 조건부인 평가 불확실성이며, 학습 데이터 추출과 학습 과정 전체의 불확실성은 포함하지 않는다. pseudo-p의 해상도는 부트스트랩 반복 2,000회에 묶여 있어(최소 달성 가능 p는 약 0.001) Holm 보정 후 값이 세 가설 모두 0.012로 같게 찍힌다. 이 값은 "효과 크기가 같다"가 아니라 "부트스트랩 해상도의 바닥에 닿았다"로 읽는다.

H1(CNN > 라벨 셔플 대조군, +0.299 ~ +0.374)과 H4(원래 배치 > shuffle-pos, +0.107 ~ +0.149)는 순열 p가 세 층 모두 <0.001이어서 "ΔAUROC가 0"이라는 귀무가설을 기각한다. H2(참조 기준 > CNN, +0.097 ~ +0.187)는 정식 검정을 붙이지 않았으므로 효과 추정치와 CI로만 보고하며, 세 층 모두 CI가 0을 배제한다. H3(L-none > L-exact)는 세 층 모두 추정치가 +0.005 / +0.002 / +0.024로 작고 CI가 0을 포함해 비기각이다. 세 층 모두 부호는 양(+)이며 4-1의 시드 평균 차이와 방향이 일치한다.

H3은 애초에 두 조건의 표본 집합이 달라 쌍체 비교가 성립하지 않으므로(4-1, 6-4) 비기각을 "길이 아티팩트가 없다"의 증거로 쓰지 않고, 인과 절제에 더 가까운 `PAD-rand` 쪽을 근거로 삼는다.

## 6. 해석

### 6-1. H1, H2 - 디코딩 없이 URL 유래 내용과 순서 신호에 접근한다

길이와 버전, 패딩 경계를 모두 통제한 주 조건에서 CNN은 v2 0.872, v3 0.814, v4 0.805를 냈다. 같은 층의 라벨 셔플 대조군은 0.498 ~ 0.508, 디코딩 텍스트 참조 기준(char n-gram LR)은 0.969 ~ 0.992다. 차이는
0.097 ~ 0.187로, CNN은 라벨 셔플 대조군보다 높고 텍스트 참조 기준보다 낮은 성능을 보였다. 디코딩 없이 QR 모듈 배치만 보고도 라벨을 판별하는 규칙을 학습한다는 것, 이것이 이 실험의 1차 결론이다. 문자나 n-gram을 실제로 복원(recover)했다는 주장은 쓰지 않는다. 5-B의 프로브 기준으로는 일부 URL 속성이 동결 표현에서 선형으로 접근 가능했으나 학습에 의한 접근성 향상은 제한적이었고, 해당 속성이 분류 결정에 사용되는지는 확인하지 않았다. 참조 기준 역시 천장이 아니라 강한 텍스트 베이스라인이므로, 차이의 크기는 "남은 정보량"이 아니라 "이 베이스라인과의 거리"로 해석해야 한다.

차이가 층이 올라갈수록 벌어진다는 점(0.097 → 0.158 → 0.187)도 기록해 둔다. URL이 길수록 격자에 담기는 문자 수는 늘지만 CNN이 그것을 읽어내는 난도가 함께 올라간다. v4는 전체 2,714개 중 시드 0의 학습 표본이 1,932개로 가장 적어 학습량 부족이 섞여 있을 가능성도 배제할 수 없다.

### 6-2. H4 - 성능은 공간, 순서 구조에서 온다 (핵심 결과)

고정 순열로 위치만 흩으면 CNN은 0.872 → 0.765, 0.814 → 0.671, 0.805 → 0.656으로 낮아진다(-0.107, -0.143, -0.149). 같은 순열을 적용해 재학습한 BitMLP는 0.834 → 0.834, 0.732 → 0.733, 0.690 → 0.706으로 변화가 작다. BitMLP의 가설 공간은 고정 순열에 대해 동등하며, 이 비교에서는 CNN의 하락이 더 컸다. 이 하락은 정보가 사라진 결과가 아니라 공간 구조를 쓰던 모델이 그 구조를 잃은 결과다. 여기서 가장 안전한 결론은 동일한 학습 조건에서 원래 QR 배치가 고정 순열 배치보다 SmallCNN이 분류 규칙을 학습하는 데 유리했다는 데까지다. 논문의 핵심 그림 F2는 이 2×2다.

MLP의 v4만 +0.016으로 미세하게 올랐는데, 표본이 가장 작은 층의 시드 변동(SD 0.018 ~ 0.019) 범위 안이라 방향성 있는 효과로 읽지 않는다.

### 6-3. CNN이 순서 없는 바이트 분포 이상을 본다

층별로 CNN 0.872/0.814/0.805, BitMLP 0.834/0.732/0.690, byte-hist LR 0.861/0.766/0.771이다. 순서를 완전히 버린 바이트 히스토그램 LR만으로 BitMLP와 같은 수준이 나온다. v2, v4에서는 오히려 더 높다. 그 위에 CNN이 얹는 추가 이득이 있고, 위치를 흩으면 그 이득이 사라진다. 여기까지가 자료가 말하는 것이며 결론은 "원래 배치에 유용한 구조가 있다"까지다.

성능 차이를 신호의 구성 비율로 분해하지 않는다. 옛 문서에는 "문자 조성 + 국소 비트 패턴 + 넓은 범위의 순서 구조"라는 분해 서술이 있었으나 현재 비교로는 세 성분을 가를 수 없다. 근거는 넷이다.

- **BitMLP도 위치 정보를 쓸 수 있다.** 고정 순열 뒤 재학습해도 성능이 유지된다는 것은 가설 공간이 순열에 대해 동등하다는 뜻이지, 위치를 못 쓴다는 뜻이 아니다.
- **byte-hist LR과 CNN의 점수가 비슷해도** 두 모델이 같은 정보를 쓰는지는 알 수 없다.
- **3×3 패치 LR과 CNN의 차이**에는 수용영역뿐 아니라 비선형성, 모델 용량, 학습 방식이 함께 섞여 있다.
- **코드워드 셔플은 QR 코드워드의 다중집합을 보존하는 것이지 URL 바이트 히스토그램을 보존하는 것이 아니다.** 헤더, 패딩, 오류정정 코드워드가 함께 들어 있으므로 "바이트 조성을 보존한 대조"라고 읽으면 과하다.

연구 대상의 범위도 좁게 잡는다. 입력은 정규화된 URL 문자열에서 합성한 QR 격자다. 전체 소문자화와 말미 `/` 제거는 경로와 쿼리의 의미까지 바꿀 수 있으므로, 여기서 말하는 신호는 그 정규화를 거친 문자열에 대한 것이다.

### 6-4. H3 - 길이 통제 전후의 성능 비교

**단서(중요)**: `L-none`과 `L-exact`는 표본 수, 클래스 구성, URL 집합이 함께 달라진다(예: v2는 exact
12,118, none 16,627, 표 T2). 두 조건은 서로 다른 표본으로 학습 및 평가된다. 그래서 아래 차이는 길이 신호만 추가한 순수한 개입의 효과가 아니라 훈련 및 평가 집합 구성까지 동시에 바꾼 비교다. 같은 표본 위에서 패딩 바이트를 무작위화하고 오류정정 코드워드를 다시 계산하는 `PAD-rand`가 길이 아티팩트의 인과적 절제에 더 가깝다. 쌍체 부트스트랩도 표본이 대응되지 않아 성립하지 않으므로 이 비교는 비쌍체로만 보고한다. 5-C의 H3의 비쌍체 추정도 같은 이유로 약한 증거다.

`L-none`과 `L-exact`의 차이는 +0.005 / +0.002 / +0.024로 작다. 패딩 주기 패턴을 직접 깨는 `PAD-rand`도
`L-none` 대비 -0.015 / -0.021 / -0.030에 그친다. 길이 단독 LR은 통제를 완전히 푼 `L-none`에서조차 0.543 / 0.544 / 0.610이다. version LR은 층 안에서 버전이 고정이므로 정의상 0.500이다.

길이 매칭을 적용한 뒤에도 분류 성능이 유지되었다. 다만 매칭 전후 표본 구성이 달라지므로 점수 차이만으로 길이 편향의 기여량을 추정할 수 없다. 또한 길이 주변분포를 맞추더라도 다른 특징과의 상호작용까지 제거되지는 않는다.

### 6-5. 정규화가 성능의 5 ~ 9%p를 좌우한다

`raw`의 AUROC는 `norm`보다 +0.049 / +0.060 / +0.087 높았다. 정규화는 소문자화, 선행 `www.` 제거, 말미 `/` 제거를 포함하며 중복과 라벨 충돌 제거 후 표본도 달라진다. 이 차이는 정규화 조건에 대한 민감성을 보여 주지만 특정 조작이나 출처 편향의 기여량을 분리한 값은 아니다.

### 6-6. 마스크

mask-auto는 -0.124 / -0.135 / -0.130으로 크게 떨어진다. 반면 mask-off는 mask-fixed와 사실상 동일하다 (-0.001 / -0.011 / +0.011). maskindex LR은 0.524 / 0.486 / 0.517로 우연 수준이다.

세 결과는 마스크 조건에 대한 민감성을 보여 준다. 원인은 아직 가설이다. 마스크 인덱스 자체가 라벨의 프록시라는 설명은 지지되지 않는다. 남은 설명 후보는 자동 마스크에서 URL에 따라 서로 다른 마스크가 선택되어 표본 간 패턴의 대응 관계가 달라진다는 것인데, 이 연구는 그 기제를 직접 측정하지 않았다.

### 6-7. 기능 패턴, path+, EC-M

- **feat-all vs data_only**: +0.001 / -0.012 / +0.008. 차이 없다. 기능 패턴(파인더, 타이밍, 정렬)은 층 안에서 상수 입력이므로 예상대로 정보를 더하지 않는다. Grad-CAM enrichment가 function 영역에서 0.49 ~ 0.66으로  1보다 작은 것(5절)도 같은 방향이다.
- **path+**: v2에서 0.727로 뚜렷이 낮아지지만(주 조건 0.872) 라벨 셔플 대조군보다는 한참 위다. v3 0.766, v4 0.822로 층이 올라갈수록 회복한다. 이 부분집합은 참조 기준 자체도 v2에서 0.914로 낮아지므로 (주 조건 0.969) 평가 표본의 구성과 난이도 변화가 함께 반영되었을 수 있다.
- **EC-M**: v3에서 0.847. 다만 EC 레벨을 바꾸면 같은 URL이 다른 용량, 다른 층으로 이동해 표본 구성이 달라진다(n 10,482 대 9,178, 참조 기준 0.961 대 0.972). 주 결과와 직접 비교할 수 없고 강건성 확인으로만 쓴다.

## 7. Bag-of-QR-patches (RQ3 직접 검정)

데이터 모듈 위를 stride 1 sliding window로 훑어 2×2, 3×3 이진 패치의 출현 빈도 히스토그램을 만들고 그 히스토그램만으로 LR을 돌린다. 창 전체가 데이터 모듈인 경우만 세고, split은 주 조건의 것을 같은 시드로 재현하므로 CNN 실험과 정확히 같은 train/val/test를 쓴다. CNN 재학습 없이 LR을 적합하므로 CPU에서 층당 수 분이면 끝난다. 셀은 `AUROC [시드 층화 그룹 클러스터 부트스트랩 95% CI]`로, CNN 표(2 ~ 4절)와 같은 estimator다.

표에는 within-QR 셔플 null 두 판이 함께 들어 있다. 7절의 결과를 국소 공간 의존성으로 올려 쓰려면 조성 차이만으로 재현되지 않는다는 것을 보여야 하기 때문이다. 같은 split, 같은 5시드에서 QR마다 데이터 모듈의 0/1 개수를 그대로 보존한 채 위치만 섞었다. 모듈 셔플은 데이터 모듈 전체에 걸쳐 위치를 무작위로 섞어 전체 비트 조성만 남긴다. 코드워드 셔플은 코드워드(8모듈) 경계를 유지한 채 코드워드 단위로 섞어 QR 코드워드의 다중집합을 보존한다. URL 바이트 조성을 보존하는 것은 아니다. 후자가 더 엄격한 null이다.

### 해석

3×3 패치 히스토그램 LR의 AUROC는 0.740 / 0.707 / 0.715였다. 각 QR 안에서 모듈 값을 섞으면 0.498 / 0.502 / 0.510, 코드워드 순서를 섞으면 0.547 / 0.539 / 0.555로 낮아졌다. 모듈 셔플이 전체 흑백 비트 개수를 보존한다는 점에서, 원래 패치 분포의 판별력을 비트 조성만으로 설명하기는 어렵다. 다만 코드워드 셔플이 보존하는 것은 헤더와 패딩, 오류정정 코드를 포함한 QR 코드워드의 다중집합이며 원본 URL 바이트 히스토그램은 아니다. 성능 차이를 국소 구조의 인과적 기여량으로 계산할 수도 없다.

motif의 위치가 기여하는 몫은 작다. 전역 히스토그램에 2×2 사분면 넷을 덧붙인 spatial pyramid는 v2에서 0.740 → 0.814로 올라가지만 v3는 0.707 → 0.712, v4는 0.715 → 0.743에 그친다. 차원을 512에서 2,560으로 늘린 대가치고는 v3, v4의 이득이 없다시피 하다. v2에서만 크게 오른 것도 격자가 작아(창 219개) 사분면 분할이 상대적으로 굵은 위치 정보를 준 결과로 읽는 편이 안전하다. 지금 자료로는 motif의 절대 위치가 판별에 중요하다고 말하기 어렵다.

CNN(0.872 / 0.814 / 0.805)과 3×3 패치 LR(0.740 / 0.707 / 0.715) 사이에는 성능 차이가 있다. 넓은 범위의 배치가 가능한 설명이지만, 비선형성, 모델 용량 및 최적화 차이도 함께 존재한다. 따라서 이 차이를 긴 범위의 순서 정보가 차지하는 몫으로 해석하지 않는다.

### C 결과와의 연결

여기서 뽑은 상위 motif가 CNN 판단의 원인인지는 5-A의 절제가 답한다. 개정된 절차에서 나온 답은
**지지되지 않음**이다. 표적 개입의 ΔAUROC(-0.014 ~ -0.045)가 개수, 위치 및 밀도를 맞춘 무작위 개입 (-0.014 ~ -0.033)과 같은 크기다. 두 개입의 차이 ΔΔAUROC는 CI가 0을 포함하거나 경계에 걸린다. 옛 문서가 "원인이기는 하되 작은 몫"이라고 적었던 것은 무작위 대조의 로짓을 평균한 뒤 AUROC를 잰 데서 나온 인공물이었다. 따라서 7절이 지지하는 것은 클래스와 연관된 국소 패치 빈도 분포의 존재까지이고 그 분포를 구성하는 특정 motif 위치가 CNN 결정의 원인이라는 데까지는 가지 않는다. RQ3의 앞부분은 절반만 답한 셈이다. 뒷부분, 새 도메인, 새 데이터셋에서의 재현성은 10절이 답한다.

## 8. 한계

1. **benign이 Alexa 계열 상위 사이트에 치우쳐 있다.** WebPhish의 ham은 인기 도메인 목록에서 왔고 phishing은 신고 기반이다. "피싱 대 정상"이 아니라 "신고된 URL 대 인기 URL"을 풀고 있을 여지가 남는다.  6-5의 정규화 민감도(선행 `www.`, 대소문자로 5 ~ 9%p)가 이 편향의 한 단면이다. 외부 세트에서 Tranco 조인을 끈 unranked Common Crawl benign이 primary와 거의 같은 결과를 준 것(10절)이 이 축의 크기를 위에서 한 번 제한해 준다. 다만 경로 편향은 외부 세트로도 통제되지 않는다 - 두 데이터셋 모두 benign 쪽 경로 보유율이 높고 부호가 같다(10절). 이 축은 `path_lr` 기준선과 길이+경로 동시 매칭 평가 집합으로 분리했다. 그 뒤 남는 전이 신호는 0.649 / 0.639 / 0.677이다(10절).
2. **v5+ 폐기로 주장 범위가 좁다.** 결론은 URL 18 ~ 78바이트, QR v2 ~ v4 구간에 한정된다. 긴 URL 구간은 엄격 길이 매칭 후 클래스당 266개만 남아 검정력이 없다. 외부 세트에서는 v5plus가 F-b로 살아났지만 WebPhish 쪽 참조가 없어 하락폭을 잴 수 없다(10절).
3. **F-c(역방향 전이)와 F-d(혼합 학습)를 실행하지 않았다.** 실행 인자가 `modes=("a","b")`였다. 따라서 "어느 쪽 신호가 더 일반적인가"라는 비대칭 질문과 "두 도메인 공통 신호가 있는가"는 답하지 못했다. F-a의 하락이 WebPhish 특이성 때문인지 외부 세트 특이성 때문인지 가르는 데 F-c가 필요하다.
4. **외부 phishing의 신선도가 세트마다 다르다.** primary인 OpenPhish는 수집 시점 기준 최근 90일이지만 secondary인 Phishing.Database `phishing-links-ACTIVE.txt`의 마지막 갱신은 2025-12-22이라 역사적 아카이브다. "active phishing"이라는 표현을 쓰면 안 된다.
5. **외부 benign의 라벨 오염을 실측하지 않았다.** 수동 검토를 하지 않아 `contamination_estimate.p_hat`이 null이다. 피싱 피드 eTLD+1 제거와 호스팅 블록리스트만 걸었고 VirusTotal, Safe Browsing 검사는 없다. 오염은 일반적으로 전이 성능을 감쇠시키는 방향으로 예상되지만 라벨 잡음이 systematic하면 단조성이 보장되지 않는다.
6. **`L-none` v4의 클래스 불균형**(1,404 대 2,526)이 6-4의 잔여 해석을 제한한다.
7. **절제 개입이 규격을 벗어난다.** `PAD-rand`와 5-A의 motif 표적 중심 비트 개입 모두 QR 규격이나 오류정정 관계를 보존한다고 보장할 수 없다. 모델 입력에 가한 개입으로서는 유효하지만 실제 QR 변형으로 해석해서는 안 된다.
8. **프로브의 음성 결과는 선형 프로브에 한정된다.** 비선형 프로브나 문자 시퀀스 디코더는 시도하지 않았다.
9. **G의 검정력이 빠듯하다.** 고정 T에서 A의 train에 형제를 실제로 보유한 행이 v2 38 / v3 35 / v4 15개다. 나머지 행은 애초에 누출 기회가 없으므로 전체 ΔAUROC가 구조적으로 희석된다. v4는 T 자체가 378행이라 특히 약하다. 11절이 보인 것은 전체 T에서 누출 이득의 단측 상한을 0.02 아래로 한정했다는 데까지이며, 누출 기회가 있는 부분집합에서는 검출도 배제도 하지 못했다.
10. **전이 판정이 평가 집합 정의에 민감하다.** 같은 데이터에서 길이만 맞추면 0.744 / 0.702 / 0.693이다. 길이×경로 유무까지 맞추면 0.649 / 0.639 / 0.677이다. 어느 쪽을 주 판정으로 삼느냐가 결론의 크기를 바꾸며, 후자를 주 판정으로 정한 것은 결과를 본 뒤의 사후 개정(2026-09-09)이다. 매칭이 맞추는 것은 길이와 `path_depth >= 1`의 결합 분포뿐이고, 매칭은 평가 표본 자체도 바꾸므로(v2 primary  15,480 → 7,260) 두 숫자의 차이를 경로 편향의 인과적 기여량으로 읽을 수 없다.
11. **motif 절제의 음성 결과는 검정력의 한계와 구분되지 않는다.** 5-A의 ΔΔ CI가 0을 포함한다는 것은 차이가 없다는 뜻이 아니라 이 표본과 이 개입 설계로 차이를 검출하지 못했다는 뜻이다. v4는 시드 간 SD가 0.023 ~ 0.027로 특히 크다.
12. **결론 두 건을 자체 정정했다.** motif의 인과 기여(5-A)는 대조군 계산 방식과 시드 통합 방식을 고치자 사라졌다. 다만 두 수정을 동시에 했으므로 원인을 둘 중 하나에 배분할 수 없다. 어휘 정보의 선형 접근성(5-B)은 표 생성기 폴백 때문에 "2/91"로 잘못 보고되었고, 시드 캐시를 복원해 재집계한 정확값은 v2 26/91, v3 13/114, v4 1/104이다. 남은 결론들도 같은 종류의 절차 의존성을 가질 수 있다.
13. **사후 재분석 항목이 있다.** SESOI 0.02 판정 규칙(2026-09-09)과 길이×경로 유무 매칭 평가 집합을 주 판정으로 바꾼 결정(2026-09-09)은 기존 결과를 확인한 뒤 도입했다. 사전 등록이 아니라 사후 재분석이다.

## 9. 후속 과제

논문 초안과 F1~F7 그림은 작성되었다. 현재 원고는 `docs/PAPER_DRAFT.md`, 그림 설명은 `reports/figures/captions.md`를 참조한다.

1. 역방향 전이(F-c)와 혼합 학습(F-d)으로 전이 비대칭과 공통 학습의 효과를 점검할 수 있다. 역방향 전이만으로 성능 저하 원인을 식별할 수는 없다.
2. 비선형 프로브와 문자 시퀀스 디코더로 현재 선형 분석의 범위를 확장할 수 있다.
3. 표현에 대한 개입으로 예측 가능한 속성이 실제 분류 결정에도 사용되는지 확인할 수 있다.
4. 외부 motif 개입은 이번 실행 범위에서 제외했다. 내부의 불확실한 결과가 외부 개입의 연구 가치까지 부정하는 것은 아니다.

## 10. 외부 검증 (F)

WebPhish로 학습한 모델을 다른 데이터셋에 재학습 없이 적용해 RQ3의 뒷부분에 답한다. primary 세트는 OpenPhish
`public_feed` 최근 90일(고유 URL 43,990건)과 Common Crawl `CC-MAIN-2026-34` × Tranco 조인 benign이다. secondary는 Phishing.Database `phishing-links-ACTIVE.txt`와 같은 benign이다. 외부에도 WebPhish와 동일한 순서(층 필터 → eTLD+1 그룹 분할 → split별 엄격 길이 매칭)를 적용한다. 임계값은 WebPhish val에서 고른 값을 그대로 쓴다. F-a는 고정 외부 평가 집합(시드 0의 절차로 한 번 만들어 얼린 행 집합에 시드 0 ~ 4의 다섯 모델을 모두 평가)로 보고한다. 시드별 평가 집합은 F-b와의 쌍체 비교용 보조다. 바닥선은 라벨 셔플이 아니라 외부 라벨을 그룹 단위로 순열해 얻은 AUROC 분포의 97.5 백분위이며, 재실행에서 설계 목표대로 2,000회를 채웠다. 그룹 순열이 양성 총수를 보존하지 않는 문제를 대조하기 위해 행 단위 순열 대조 기준값도 함께 싣는다 (표의 `행순열 대조 기준값` 열, 0.503 ~ 0.520). 기준선은 CNN과 같은 5시드, 같은 평가 행에서 다시 계산해 쌍체 ΔAUROC와 CI를 붙였다.

출처 편향의 방향 (2026-09-09 정정). 이 절의 옛 서술은 "WebPhish는 benign이 짧고 경로가 없는데 외부는 그 방향이 뒤집혔다"였다. 틀렸다. `reports/external/bias_stages.json`의 단계별 통계를 보면
`path_depth>=1` 비율이 원본에서 WebPhish benign 99.7% 대 phishing 69.8%, 외부 benign 93.9% 대 phishing 46.0%다. v2 길이 매칭 후에도 99.75% / 44.3% 대 86.8% / 33.7%다. 두 데이터셋 모두 benign 쪽 경로 보유율이 훨씬 높으며 부호가 전 층에서 같다. WebPhish benign은 맨 도메인 코퍼스가 아니라 경로를 가진 심층 페이지 코퍼스다. 라벨 매핑(`spam`→phishing, `ham`→benign)은 재확인했고 문제가 없다.

따라서 외부 세트는 편향을 뒤집는 stress test가 아니라 같은 방향의 편향을 공유하는 세트다. 게이트는 차단이 아니라 플래그 방식으로 재설계했고(`docs/EXTERNAL_VALIDATION_DESIGN.md` 6.1절), 경로 모양의 기여를 점검하는 장치를 둘 두었다. 하나는 path-shape LR 기준선이고 - 입력은 `qrphish.urls.shape_features()`가 만드는 6차원, 즉 경로 유무, 경로 깊이와 `/`, `.`, `-`, `?`의 개수다 - 다른 하나는 **길이×경로 유무 매칭** 평가 집합(`a_fixed_lenpath`)다. 매칭이 맞추는 것은 길이와 `path_depth >= 1`의 결합 분포뿐이고 경로 깊이 자체나 구분자 구성, 쿼리 구조 전체가 아니다. 후자가 주 판정이고 길이만 맞춘 평가 집합은
`reported_unmatched_path`로 표시해 서술용으로만 남긴다. 주 판정을 이쪽으로 바꾼 것은 기존 결과를 확인한 뒤의 사후 개정(2026-09-09)이며 사전 등록이 아니다.

### 해석

길이만 맞춘 평가 집합의 점수에는 경로 shortcut이 섞여 있다. primary에서 CNN은 0.744 / 0.702 / 0.693인데, 같은 평가 집합에서 경로 모양만 쓰는 path-shape LR이 0.780 / 0.638 / 0.602다. v2에서는 이 기준선이 CNN을 넘고(쌍체 Δ = CNN - path -0.036 [-0.081, +0.016]) v3, v4에서도 CNN과 같은 구간이다. 경로 유무, 깊이와 네 구분자 개수만 쓰는 6차원 특징만으로도 이만한 전이 성능이 나온다는 뜻이며, 두 데이터셋이 같은 방향의 편향을 공유할 가능성을 보여 준다. 그러니 이 평가 집합의 숫자를 "QR 공간 신호의 전이"로 해석해서는 안 된다. 세 층 모두 `reported_unmatched_path`로 표시했다.

길이×경로 유무까지 맞추면 신호가 줄되 바닥선 위에 남는다. `a_fixed_lenpath` 평가 집합에서 CNN은 0.649 [0.626, 0.670] /
0.639 [0.609, 0.667] / 0.677 [0.639, 0.724]다. 순열 대조 기준값은 0.530 / 0.537 / 0.558, 행 단위 순열 대조 기준값은
0.506 / 0.505 / 0.506이다. CI 하한이 세 층 모두 두 바닥선 위다. 같은 평가 집합에서 path-shape LR은
0.509 / 0.394 / 0.542로 내려간다. CNN 대비 쌍체 Δ는 +0.140 [+0.106, +0.174] / +0.244 [+0.166, +0.312] / +0.135 [+0.059, +0.259]로 뒤집힌다. 즉 경로 모양을 통제하고 나면 CNN이 그 기준선보다 뚜렷이 낫다. 판정은 v2 `partial_collapse`, v3, v4 `reproduced_weak`다. WebPhish 내부 성능(0.872 / 0.814 / 0.805) 대비 하락폭은 -0.223 / -0.175 / -0.128로 길이만 맞췄을 때보다 커졌다.

여기서 0.744 → 0.649를 경로 shortcut의 인과적 기여량으로 해석해서는 안 된다. 매칭은 평가 표본 자체를 바꾼다. v2 primary 기준으로 평가 n이 15,480에서 7,260으로 줄고 남는 행의 구성과 난이도도 함께 달라진다. 이 하락은 전이 점수가 경로 편향에 민감하다는 근거는 되지만 개별 요인의 기여량은 아니다. path-shape LR이 낮아졌다고 경로 정보가 모두 사라진 것도 아니다. v3의 0.394는 중립값 0.5와 다르며 학습된 구조적 관계의 방향이 외부 평가 집합에서 뒤집혔을 가능성을 시사한다. 한 선형 기준선의 전이 실패가 그 특징군 전체의 예측력 부재를 입증하지는 않는다.

텍스트 기준선이 CNN보다 잘 전이된다. 이제 같은 5시드, 같은 평가 행에서 계산한 쌍체 Δ로 말할 수 있다.
`a_fixed_lenpath` primary에서 char n-gram LR은 0.714 / 0.834 / 0.796이다. Δ(CNN - char n-gram)는 -0.065 [-0.087, -0.042] / -0.195 [-0.236, -0.153] / -0.119 [-0.190, -0.057]로 세 층 모두 CI가 0을 배제한다. 다른 외부 세트까지 합치면 이 Δ는 -0.09 ~ -0.24 구간에 흩어진다. 반면 byte-hist LR과의 Δ는 +0.005 [-0.028, +0.037] / +0.044 [-0.012, +0.098] / -0.015 [-0.076, +0.035]로 세 층 모두 CI가 0을 포함한다. 즉 "외부에서도 QR의 공간 표현을 쓰는 CNN이 단순한 문자 조성보다 추가 이점을 준다"는 주장은 근거가 부족하다. 두 모델이 동등하다고 입증한 것은 아니다. motif-hist LR(3×3)은 0.576 / 0.559 / 0.591로 가장 낮고 CNN이 +0.073 ~ +0.086 앞선다. 비교한 모델 중에서는 문자 n-gram LR이 CNN과 motif-hist LR보다 높은 외부 성능을 보인다.

외부 데이터로 학습하고 분리된 외부 표본에서 평가한 F-b의 AUROC는 0.892 / 0.918 / 0.868이었다. 외부 데이터 안에도 학습 가능한 라벨 연관성이 있지만, 이것만으로 F-a의 성능 저하 원인을 구분할 수는 없다. F-b의 v2는 path-shape LR이 0.849로 높아 `descriptive_only`로 분류했다. v3와 v4는 `reproduced_strong`, v5plus는 내부 참조가 없어 `reproduced_unknown_reference`다.

시험한 설정 변경에서 결과는 대체로 유지된다. 정제 절제 두 조건(피싱 도메인 유지, 호스팅 블록리스트 미적용)은 길이 매칭 평가 집합에서 primary와 소수점 셋째 자리까지 사실상 같다. 후자는 primary benign에서 한 건도 제거하지 않는 no-op임이 수집 단계에서 확인됐으므로, 절제로서의 정보량이 없다는 사실 자체가 결과다. Tranco 조인을 끈 unranked Common Crawl benign은 길이+경로 매칭에서 0.636 / 0.604 / 0.666으로 primary와 같은 구간이다. secondary(Phishing.Database)는 길이+경로 매칭에서 0.652 / 0.700 / 0.760이다. v4만
`reproduced_strong`, v3 `reproduced_weak`, v2 `partial_collapse`다. 인기 도메인 confound와 benign 정제 낙관 편향을 겨냥해 시험한 설정 변경에서는 결과가 대체로 유지됐다는 뜻이며, 그 편향이 없다는 증명은 아니다.

개별 motif는 대체로 재현되지 않는다. primary 고정 평가 집합에서 512종 log OR의 Spearman ρ가
0.228 [0.113, 0.256] / 0.066 [0.019, 0.109] / 0.073 [-0.018, 0.142]다. CI 하한이 0.2를 넘는 층이 하나도 없다. 상위 20 부호 일치율은 0.850 / 0.500 / 0.650으로 v2만 귀무(0.5)를 배제한다. 상위 20 Jaccard는
0.026 / 0.053 / 0.000으로 귀무 상한 0.081 이하다. 판정은 v2 `partial`, v3, v4 `failed`다. secondary는 v2만
`reproduced`이고 v3, v4는 `partial`이다. 전 세트를 합치면 ρ 0.03 ~ 0.32, 부호 일치율 0.45 ~ 0.90 구간에 흩어진다. 여기 쓰인 WebPhish 쪽 motif 목록도 시드별 선정 절차에서 다시 뽑은 것이다.

세 결과를 합치면 방향은 하나다. 출처와 구조의 차이(길이, 경로 모양)를 통제한 뒤 남는 전이 신호는 작지만 순열 대조 기준값을 넘는다. 그리고 그 신호는 텍스트 기준선만큼 잘 전이되지 않으며, 개별 motif의 정체는 데이터셋 특이적이다. RQ3의 뒷부분의 답은 "약하게 그렇다"이고 "피싱 QR에 보편적인 시각 signature가 있다"는 문장은 이 결과로 지지되지 않는다.

## 11. 템플릿 누출 (G)

eTLD+1만 격리한 분할이 phishing kit, 경로 템플릿 수준의 누출을 놓치고 있는지 본다. 설계를 한 번 변경했다.
1차 분할과 템플릿 분할을 각각 돌려 비쌍체로 빼던 옛 방식은 1차 test 행의 86 ~ 88%가 교체됐고 test 평가 집합 Jaccard도 0.06 ~ 0.10이었다. 그래서 효과를 분리할 수 없어 폐기했다. 지금은 URL 토큰, 경로 템플릿의 MinHash 클러스터와 eTLD+1을 union-find로 합친 성분 단위로 캠페인 test 집합 T를 하나 고정한다. 그 위에서 학습 조건만 다른 두 모델을 쌍체 비교한다. Model A는 eTLD+1만 격리(T와 같은 캠페인의 다른 도메인, 즉 형제 행을 train에 허용), Model B는 eTLD+1과 템플릿까지 격리한다. 주 지표는 형제를 전부 둔 채 비형제를 덜어 `|train| = |train_B|`로 맞춘
`A_sm`과 B의 차이 ΔAUROC = A_sm - B다. 세 모델이 같은 T를 평가하므로 전부 쌍체다.

- 누출 대조 부분집합은 표본이 수십 행뿐이라 CI가 넓다. 현재 CI로는 `negligible`을 뒷받침하지 못하며, "phishing kit 암기 가능성을 배제했다"는 결론의 근거로 쓸 수 없다.

### 해석

판정 규칙을 고친 시점을 분명히 적는다. 옛 규칙은 "쌍체 CI 하한이 0 이하이면 누출 무시 가능"이었다. 이 규칙은 CI가 `[-0.10, +0.30]`처럼 큰 양의 효과까지 허용해도 같은 판정을 내주므로, 비유의성을 효과 부재로 읽게 만든다. **기존 결과를 확인한 뒤, 비유의성을 효과 부재로 해석하는 문제를 수정하기 위해 AUROC 0.02를 기준으로 사후 재분석하였다**(2026-09-09). 같은 캠페인 추정치와 CI는 이 규칙을 적기 전에 이미 계산되어 있었으므로 사전 등록이 아니다. CI 상한이 0.02 미만일 때만 `negligible`이고 CI가 0을 포함하되 상한이 0.02 이상이면 `not_detected`. 검출도 배제도 못한 상태다.

이 판정은 누출 이득의 단측 상한 평가이지 양방향 등가성 주장이 아니다. v4의 CI `[-0.042, +0.015]`는 상한이 0.02 아래여서 `negligible`이지만 구간 자체는 ±0.02 안에 들어가지 않는다.

주 지표는 세 층 모두 `negligible`이다. ΔAUROC(A_sm - B)가 -0.010 / +0.001 / -0.014다. 쌍체 95% CI 상한은 0.0011 / 0.0145 / 0.0151로 셋 다 SESOI 0.02 아래다. 그룹 단위 교환 클러스터 순열 p도
0.496 / 0.946 / 0.742다. Model B의 AUROC도 0.851 / 0.774 / 0.828로 라벨 셔플 대조군보다 한참 위라 "결론 무효" 칸에는 걸리지 않는다. 여기까지가 이 실험이 보인 것이다. 정의한 템플릿 분리 방식과 평가 집합에서 누출 허용에 따른 전체 AUROC 상승의 상한을 0.02 아래로 한정했다.

누출 기회가 있는 행만 보면 검출도 배제도 못했다. T 표본은 1,688 / 1,273 / 378행인데 그중 A의 train에 형제를 실제로 보유한 행은 시드당 평균 38 / 35 / 15개다. 나머지 행에는 애초에 누출 기회가 없으므로 전체 ΔAUROC는 구조적으로 희석된다. 누출 행만 따로 본 부분집합 지표는 +0.017 / +0.064 / +0.028로 부호가 셋 다 양(+)이다. CI 상한이 0.09 ~ 0.16이라 판정은 전부 `not_detected`다. 표본이 수십 행뿐이라 이 부분집합에서
현재 결과로는 `negligible`이라고 판단할 수 없다. phishing kit 암기 가능성을 배제한 것은 아니다. URL 템플릿 클러스터가 실제 공격 캠페인의 완벽한 정답 라벨도 아니다. 이 지표는 표본 구성이 달라 전체 T의 Δ와 크기를 직접 비교해서도 안 된다.

분할 자체는 의도대로 작동했다. B의 train에 T와 템플릿이 겹치는 행은 세 층 모두 0행이고 A에는
44 / 32 / 15행이 있다.

옛 비쌍체 G의 차이는 분해되지 않는다. 옛 방식은 1차 test 행의 86 ~ 88%가 교체된 상태에서 두 조건을 비교했다. 따라서 그때 본 0.08 수준의 격차를 두고 지금 말할 수 있는 것은 옛 비교가 test 교체 효과와 누출 효과를 분리할 수 없었다는 데까지다. "그 차이는 test 교체 효과였다"고 단정하지 않는다.

텍스트 베이스라인의 Δ도 0 근처다. Δ char n-gram LR은 -0.000 / +0.001 / -0.000, Δ byte-hist LR은 +0.002 / +0.000 / +0.001이다. 어휘 수준에서도 템플릿 누출로 얻는 이득은 관측되지 않았다. 크기를 맞추지 않은 보조 지표 `A - B`는 -0.011 / +0.014 / +0.009다. 판정은 v2 `negative`, v3 `detected_minor`, v4 `not_detected`로 층마다 갈린다. v3에서 CI 하한이 0을 넘는다는 점은 기록해 둔다. 크기를 맞추지 않으면 학습 표본 수 효과가 Δ에 섞이므로 주 지표는 `A_sm`이지만, 보조 지표가 층 하나에서 작은 이득을 검출했다는 사실을 지우지는 않는다.
