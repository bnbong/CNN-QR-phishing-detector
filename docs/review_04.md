**이번 개정은 연구의 신뢰도를 상당히 높였습니다. 다만 논문에 넣기 전에 반드시 바로잡아야 할 프로브 집계 오류가 하나 남아 있습니다.** 제 평가는 “통제 실험 논문으로 발전시킬 가치가 충분하지만, 현재 보고서를 그대로 투고하기에는 중요한 수정이 필요하다”입니다.

특히 긍정적으로 보는 것은, 수정 후 성능과 해석이 약해졌는데도 이를 보고서에 반영했다는 점입니다. 연구의 가치는 처음 생각한 가설을 끝까지 입증하는 데 있지 않습니다. **어떤 관찰이 통제를 견디고, 어떤 해석이 대조군을 바로잡자 사라지는지 밝혀낸 것**도 연구 결과입니다.

검토 기준은 커밋 [`a56bbf2`](https://github.com/bnbong/CNN-QR-phishing-detector/tree/a56bbf251332a4d921fa24c1e4b0577182b90a3d)입니다. 요청대로 `review_01.md`~`review_03.md`는 제외했습니다. 현재 실험 코드·설정·노트북·테스트·문서·결과 JSON을 대조했고, Python 파일 47개와 JSON 121개의 구문을 확인했습니다. 프로브 표 생성도 직접 실행해 아래 오류를 재현했습니다. 다만 원본 데이터와 체크포인트로 전체 학습을 재실행한 독립 재현은 아닙니다.

**먼저, 이전 문제 중 실제로 해결된 부분을 평가하겠습니다.**

motif 수정은 설명만 바뀐 것이 아닙니다. 실행 결과에 새 대비와 시드별 선정 경로가 들어 있고, 선정 함수의 상위 motif 선택도 train 통계를 사용합니다. 이 부분은 분명한 개선입니다. [선정·집계 코드](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/qrphish/runner.py), [절제 코드](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/qrphish/occlusion.py)

**가장 중요한 문제는 “어휘 정보의 접근성도 확인하지 못했다”는 새 결론입니다. 현재 자료로는 이 결론을 낼 수 없습니다.**

보고서 4.7에서는 다음 세 수가 모두 `2/91, 0/114, 0/104`로 같습니다.

* `accessible`: 학습 표현이 셔플 기준선을 넘는가?
* `learned_gain`: 학습 표현이 미학습 CNN 표현을 넘는가?
* `accessible_and_gained`: 둘 다 만족하는가?

그런데 공개된 프로브 JSON에는 새 `accessible` 집계가 없습니다. 표 생성기의 `table_probes()`는 새 필드가 없으면 **세 질문 모두에 옛 `n_significant`를 대신 출력**합니다.

```python
else:  # 재요약 전의 옛 결과
    cells.append(f"{summ.get('n_significant', '—')} / {summ['n_targets']}")
```

직접 실행해 보고서와 같은 표가 생성되는 것을 확인했습니다. 즉, 세 결과가 같다는 것은 새 실험에서 세 질문의 답이 우연히 같아졌다는 증거가 아닙니다. **누락된 서로 다른 값을 같은 옛 값으로 대체한 결과입니다.** [표 생성 코드](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/scripts/make_results_tables.py)

구체적으로 v2의 `ngram:jp.`에는 다음 값이 저장되어 있습니다.

| 항목                    |   저장값 |
| --------------------- | ----: |
| 학습 표현 점수              | 0.909 |
| 학습 표현의 시드 평균 CI 하한    | 0.865 |
| 셔플 기준선의 시드 평균 CI 상한   | 0.587 |
| 미학습 표현 점수             | 0.849 |
| 미학습 표현의 시드 평균 CI 상한   | 0.908 |
| `n_seeds_significant` |     0 |

여기서 마지막 `0`은 **셔플과 미학습 기준선을 모두 넘은 시드가 0개**라는 뜻입니다. 이를 “셔플 기준선을 넘은 시드가 0개”로 해석할 수 없습니다. 보고서의 “점수가 높지만 접근성 통과 시드가 0개”라는 설명은 이 두 판정을 혼동하고 있습니다. [v2 프로브 원결과](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/reports/probes/norm-exact-data_only-fixed-small_cnn/v2/results.json)

제가 저장값을 재계산한 결과는 다음과 같습니다.

| 저장 자료로 확인 가능한 항목      |           v2 |           v3 |           v4 |
| --------------------- | -----------: | -----------: | -----------: |
| 전 시드 `learned_gain`   |            2 |            0 |            0 |
| 전 시드 두 기준선 동시 통과      |            2 |            0 |            0 |
| 평균 CI를 이용한 접근성 **근사** |           45 |           30 |            6 |
| 전 시드 접근성의 **정확한 수**   | 공개 자료로 복원 불가 | 공개 자료로 복원 불가 | 공개 자료로 복원 불가 |

**45·30·6을 정확한 결과로 다시 채택하라는 뜻은 아닙니다.** 평균 CI로는 전 시드 통과 여부를 알 수 없습니다. 공개 JSON의 `per_seed`에는 표본 수만 있고, 목표별 시드 CI가 없기 때문입니다.

필요한 조치는 비교적 좁습니다.

1. 새 필드가 없으면 `n_significant`를 대신 넣지 말고 “미집계”로 표시합니다.
2. Drive 등에 `seed{k}.json`이 남아 있으면 그것으로 정확히 재집계합니다.
3. 없다면 기존 CNN 체크포인트에서 프로브만 다시 실행합니다.
4. 목표별·시드별 두 대비를 저장하고 표와 본문을 다시 만듭니다.

**CNN 본 학습을 전부 다시 할 필요는 없습니다.** 당장은 “학습에 의한 접근성 향상은 경로 구조 두 목표에서만 확인되었으며, 어휘 접근성 자체의 전 시드 판정은 재집계가 필요하다”가 안전한 표현입니다.

이 오류는 연구 전체를 무효로 만들지는 않지만, 보고서가 새롭게 강조한 “두 결론을 자체 정정했다” 중 프로브에 관한 정정은 다시 검토해야 합니다.

**motif 절제는 이제 훨씬 신뢰할 만하지만, 음성 결과의 범위를 정확히 써야 합니다.**

가장 적절한 비교인 phishing motif 표적 개입과 topology를 맞춘 무작위 개입의 차이는 다음과 같습니다.

| 층  | 표적−무작위 ΔAUROC | 95% CI           |
| -- | ------------: | ---------------- |
| v2 |       약 0.000 | [−0.007, +0.005] |
| v3 |        −0.009 | [−0.016, +0.001] |
| v4 |        −0.005 | [−0.020, +0.012] |

이 결과는 **“선정한 phishing motif의 중심 비트를 뒤집는 것이, 비슷한 위치·밀도에서 같은 수의 비트를 뒤집는 것보다 일관되게 더 큰 손상을 준다는 근거를 얻지 못했다”**고 해석하는 것이 맞습니다. 보고서가 이 방향으로 수정된 것은 타당합니다. [보고서 4.6](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/docs/REPORT.md#46-인과-motif-절제)

다만 다음 세 가지를 구분해야 합니다.

* 특정 motif의 **클래스별 빈도 차이**가 존재한다.
* 그 motif가 CNN 판단에 **특별히 중요하다**.
* 그 motif가 외부 데이터에도 통하는 **보편적 특징**이다.

첫 번째가 성립해도 두 번째와 세 번째는 자동으로 성립하지 않습니다. 이번 연구는 그 차이를 보여 주는 방향으로 좋아졌습니다.

또한 모든 대비가 완전히 음성인 것은 아닙니다. v3의 phishing motif−개수 대조와 v4의 benign motif 대비 일부는 CI가 0을 배제합니다. 따라서 “모든 표적 개입이 무작위 개입과 같다”로 뭉뚱그리기보다는 **주요 phishing motif 효과가 대조 조건과 시드에 걸쳐 견고하지 않았다**고 쓰십시오.

기존 결과와 수정 결과가 달라진 이유도 조심해야 합니다. 선정 누출과 로짓 평균을 동시에 고쳤으므로, 이전 결론 전체가 사라진 원인을 둘 중 하나에만 배분할 수는 없습니다. 무작위 대조의 계산 비대칭은 확실한 문제였지만, 두 수정의 기여를 정량적으로 분리한 실험은 아닙니다.

**외부 검증은 이번 연구에서 가장 설득력 있는 결과가 되었습니다. 그러나 “경로 효과를 제거했다”는 표현은 여전히 강합니다.**

주 외부 cohort의 결과를 간추리면 다음과 같습니다.

| AUROC                    |    v2 |    v3 |    v4 |
| ------------------------ | ----: | ----: | ----: |
| 내부 CNN                   | 0.872 | 0.814 | 0.805 |
| 외부 CNN, 길이만 매칭           | 0.744 | 0.702 | 0.693 |
| 외부 CNN, 길이×경로 유무 매칭      | 0.649 | 0.639 | 0.677 |
| 같은 cohort의 문자 n-gram LR  | 0.714 | 0.834 | 0.796 |
| 같은 cohort의 path-shape LR | 0.509 | 0.394 | 0.542 |

문자 n-gram LR과 CNN의 쌍체 비교는 세 층 모두 텍스트 기준선의 우세를 보여 줍니다. 반면 byte-hist LR과 CNN의 차이는 세 층 모두 CI가 0을 포함합니다. 이것은 **“외부에서도 QR의 공간 표현을 쓰는 CNN이 단순한 문자 조성보다 추가적인 이점을 제공한다”는 주장에는 근거가 부족하다**는 뜻입니다. 두 모델이 동등하다고 입증한 것은 아닙니다. [외부 검증 결과](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/docs/REPORT.md#410-외부-검증-f)

남은 해석 문제는 세 가지입니다.

첫째, `match_by_length_and_path()`가 맞추는 것은 **길이와 `path_depth >= 1`의 결합 분포**입니다. 경로 깊이 자체, 구분자 개수, 쿼리 구조 전체를 맞추는 것은 아닙니다. 논문에서는 “길이·경로 통제”보다 “길이×경로 유무 매칭”이라고 정확히 이름 붙이는 편이 좋습니다. [매칭 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/qrphish/transfer.py)

둘째, 매칭 전후에는 평가 표본도 바뀝니다. v2는 15,480개에서 7,260개로 줄어듭니다. 따라서 0.744→0.649의 하락을 **경로 shortcut의 인과적 기여량 0.095**라고 읽으면 안 됩니다. 경로 편향에 민감하다는 근거는 되지만, 표본 구성과 난이도 변화도 함께 일어납니다. 보고서의 “그 몫을 떼어냈다”는 표현은 수정하는 것이 좋습니다.

셋째, path-shape LR이 낮아졌다고 모든 경로 정보가 사라진 것은 아닙니다. 특히 v3의 0.394는 중립적인 0.5와 다릅니다. 이는 학습된 구조적 관계의 방향이 외부 cohort에서 달라졌을 가능성을 시사합니다. **한 선형 기준선의 전이 실패가 해당 특징군 전체의 예측력 부재를 입증하지는 않습니다.**

추가로 보고서는 path-shape 입력을 “세 가지”, “구분자 비율”로 설명하는 곳이 있지만 실제 `shape_features()`는 경로 유무·깊이와 `/`, `.`, `-`, `?` **개수**를 사용하는 6차원 특징입니다. 방법 절을 구현에 맞추십시오. [특징 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/qrphish/urls.py)

이 문제들을 해결하려고 지금 당장 새로운 대형 실험을 추가할 필요는 없습니다. **통제한 범위를 정확히 명시하고, 잔여 교란을 인정하면 현재 결과를 논문에 사용할 수 있습니다.**

**캠페인 분석의 새 판정은 개선됐지만, ‘등가성’과 ‘사전 등록’이라는 표현은 바꿔야 합니다.**

현재 규칙은 CI 상한이 0.02보다 작으면 `negligible`입니다. 이는 다음 주장을 뒷받침할 수 있습니다.

> 정의한 전체 평가 집합에서 누출 허용에 따른 AUROC 상승은 0.02 미만으로 제한된다.

그러나 양방향 동등성, 즉 차이가 `−0.02~+0.02` 안에 있다는 뜻은 아닙니다. v4의 CI는 `[-0.042, +0.015]`이므로 그 구간 안에 들어가지 않습니다. **“누출 이득의 단측 상한 평가”**로 설명하는 편이 정확합니다. 실제 누출 기회가 있는 부집합에서는 큰 상승을 배제하지 못했다고 구분한 것은 잘했습니다. [캠페인 결과·해석](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/docs/REPORT.md#411-템플릿-누출-g)

더 중요한 것은 시점입니다. 설계서는 2026-09-09에 SESOI 0.02 규칙을 개정하면서 이를 “사전 등록”이라고 부릅니다. 하지만 같은 캠페인 추정치와 CI는 이미 앞선 결과에 존재했습니다.

**이미 본 결과에 새 기준을 적용하는 것은 사후 재분석입니다.** 코드 실행 전에 기준을 적었다고 해서 결과를 보기 전의 사전 등록이 되는 것은 아닙니다.

이것이 분석을 무가치하게 만드는 것은 아닙니다. 다음처럼 투명하게 쓰면 됩니다.

> 기존 결과를 확인한 뒤, 비유의성을 효과 부재로 해석하는 문제를 수정하기 위해 AUROC 0.02를 기준으로 사후 재분석하였다.

외부 매칭 cohort를 주 분석으로 바꾼 과정도 최초 설계와 수정 설계의 시점을 구분하십시오. 지도교수나 심사자는 탐색적 연구 자체보다 **탐색 과정을 확증적 연구처럼 제시하는 것**을 더 문제 삼을 수 있습니다. [설계 개정 기록](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/docs/EXTERNAL_VALIDATION_DESIGN.md)

---

**통계 표는 한 번 더 정리해야 합니다. 한계에 적어 둔 것만으로 본문의 강한 판정이 정당화되지는 않습니다.**

보고서 4.9는 `pseudo-p`가 정식 p값이 아니라고 인정하면서도 “Holm 보정 후에도 기각”이라고 결론을 냅니다. 이 두 문장은 함께 유지하기 어렵습니다.

권장하는 정리는 다음과 같습니다.

* H1·H4: 실제 계산한 클러스터 순열 p값을 중심으로 보고합니다.
* H2: 현재 쌍체 효과 추정치와 CI를 보고하거나, 정식 검정을 추가합니다.
* H3: 평가 표본이 달라 직접적인 쌍체 효과로 해석하기 어렵다는 제한을 유지합니다.
* `pseudo-p (Holm)`는 정식 가설 검정 표에서 제외합니다.

표의 “CNN > 셔플 바닥 — 기각”이라는 표현도 무엇을 기각했는지 모호합니다. 귀무가설을 명시하거나 “CNN 우세 근거 있음”처럼 바꾸는 편이 읽기 쉽습니다.

외부의 `group_block_exchange_approx`와 행 순열을 함께 보고한 것은 투명성 면에서 좋아졌습니다. 다만 그룹 블록 근사는 여전히 가정이 필요한 절차입니다. **반복 수를 200에서 2,000으로 늘리면 계산 오차가 줄어들 뿐, 교환 가능성 가정이 검증되는 것은 아닙니다.** “엄밀한 순열 검정을 통과했다”보다 “정의한 그룹 블록 null 기준을 넘었다”고 표현하십시오.

또한 현재 부트스트랩 CI는 저장된 모델들의 예측에 조건부인 평가 불확실성을 주로 나타냅니다. 학습 데이터와 학습 과정 전체의 불확실성까지 포함하는 것으로 설명하지 않으면 됩니다. [통계 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/a56bbf251332a4d921fa24c1e4b0577182b90a3d/qrphish/evaluate.py)

**논문의 주장과 신규성은 이제 더 좁고 선명하게 잡을 수 있습니다.**

보고서에는 수정된 설명과 이전의 강한 설명이 아직 공존합니다. 예를 들어 5.1 앞부분은 위치 정보를 못 쓰는 모델의 성능이 바이트 주변분포로 설명된다고 쓰지만, 바로 아래에서는 BitMLP도 위치를 사용할 수 있고 비슷한 성능이 같은 정보 사용을 뜻하지 않는다고 설명합니다.

다음 표현들은 정리해야 합니다.

| 현재 표현의 문제                            | 더 적절한 표현                                                 |
| ------------------------------------ | -------------------------------------------------------- |
| QR이 무손실 인코딩이므로 분류 가능성은 정보이론적으로 자명    | 인코딩은 문자열 정보를 보존하지만, 그 정보의 라벨 예측력과 제한된 CNN의 학습 가능성은 실험 문제 |
| path LR이 높으므로 CNN 전이 성능 대부분이 경로로 설명됨 | 경로·구분자 특징만으로도 높은 전이 성능을 얻어 공유 편향 가능성을 보여 줌               |
| 공간적일수록 덜 전이됨                         | 비교한 모델 중 문자 n-gram LR이 CNN과 motif-hist LR보다 높은 외부 성능을 보임 |
| 역방향 전이도 떨어지면 표현 특이성이 원인              | 역방향 전이는 비대칭을 점검하지만 원인을 단독 식별하지는 못함                       |
| 민감도 실험에서 편향이 관측되지 않음                 | 시험한 설정 변경에서 결과가 대체로 유지됨                                  |

선행연구 비교표가 아직 “확인 필요”인 것도 투고 전에는 해결해야 합니다. 직접 확인한 Trad와 Chehab의 연구는 이미 QR 픽셀을 직접 분석하며, 고정 v13, PhishStorm 기반 데이터, 픽셀 중요도 분석을 사용합니다. 최신 공개판에는 AIAI 2026 채택도 명시되어 있습니다. 따라서 “디코딩 없는 QR 피싱 분류” 자체를 신규성으로 내세우기 어렵습니다. [선행연구 본문](https://arxiv.org/html/2505.03451v2), [논문 정보](https://arxiv.org/abs/2505.03451)

반면 당신의 연구에는 다음과 같은 차별화 가능성이 있습니다.

> **QR 분류 성능을 얻는 데서 멈추지 않고, 길이·생성 조건·공간 배치·해석 대조군·외부 분포를 통제했을 때 어떤 주장이 살아남는지 평가한다.**

이 방향은 연구 내용과 잘 맞습니다. 제목도 예를 들어 다음 정도가 적절합니다.

> **명시적 디코딩 없는 QR 기반 피싱 분류의 통제 평가: 공간 배치, 국소 패턴과 외부 일반화**

---

**교수에게 논문 지도를 받는 단계라면, 이제는 실험을 끝없이 늘리기보다 원고를 쓰기 시작할 시점입니다.**

제가 지도한다면 우선순위를 다음처럼 잡겠습니다.

| 우선순위      | 할 일                                  |
| --------- | ------------------------------------ |
| 반드시 수정    | 프로브의 정확한 재집계와 잘못된 음성 결론 수정           |
| 반드시 수정    | 사전 등록·등가성·경로 효과 제거라는 표현 정정           |
| 반드시 수정    | 정식 p값과 pseudo-p를 분리하고 방법·표·본문 불일치 제거 |
| 원고 작성에 필요 | 가까운 선행연구와 통제 조건 비교 완성                |
| 선택적 후속 연구 | 역방향 전이, 추가 데이터셋, 실제 촬영 QR, 더 강한 프로브  |

F-c·F-d나 실제 촬영 QR 실험을 모두 끝내야 논문을 쓸 수 있는 것은 아닙니다. 그런 실험은 주장 범위를 넓힐 때 필요합니다. 현재 범위를 **정규화 URL에서 합성한 QR 모듈 격자에 대한 통제 연구**로 제한하면, 먼저 원고를 작성할 수 있습니다.

심사자 관점에서 강점은 통제의 폭, 여러 종류의 기준선, 외부 검증, 수정 이력의 투명성입니다. 약점은 아직 확정되지 않은 신규성, 단일 내부 학습 출처, 프로브 집계 오류, 일부 인과적 표현입니다. 학부 졸업생의 개인 프로젝트라는 배경을 고려하면 상당히 발전한 작업이지만, 논문에서는 배경과 별개로 같은 증거 기준을 적용받습니다. **현재 남은 문제는 “연구를 할 수준이 되는가”보다 “결과와 주장을 얼마나 정확히 일치시키는가”에 가깝습니다.**

쉽게 설명하면, 지금까지의 결과는 다음과 같습니다.

* **CNN은 이 데이터의 QR을 보고 정상·피싱 라벨을 어느 정도 구분합니다.**
* **원래 QR 배치는 이 CNN이 학습하는 데 도움이 됩니다.**
* **그렇다고 모든 피싱 QR에 통하는 특정 무늬를 찾았다는 뜻은 아닙니다.**
* **특정 무늬를 골라 훼손했을 때의 특별한 효과는 견고하게 확인되지 않았습니다.**
* **새 출처에서도 약한 구분력은 남지만, URL 문자를 직접 분석한 기준선이 더 잘합니다.**
* **CNN 표현에서 문자 정보를 읽을 수 있는지는 프로브 집계를 바로잡은 뒤 다시 답해야 합니다.**

이번 연구에서 가장 설득력 있는 이야기는 “피싱 QR의 비밀 무늬를 발견했다”가 아니라, **“QR 분류 성능이 존재한다는 사실만으로 보편적 무늬나 특정 판단 원인을 주장할 수 없으며, 통제 실험이 그 해석을 실제로 바꾼다”**입니다. 이 주장을 중심으로 원고를 구성하고, 프로브 오류를 바로잡은 자료를 함께 교수님께 보여 드리는 것이 좋겠습니다.
