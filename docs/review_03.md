**논문으로 발전시킬 가치가 있습니다. 다만 현재 상태는 “흥미로운 결과를 얻은 연구 초안이며, 핵심 분석 일부를 수정해야 하는 Major Revision 수준”이라고 평가하겠습니다.**

가장 설득력 있는 성과는 **길이와 QR 버전 등을 통제해도 분류 신호가 남고, QR의 원래 공간 배치가 CNN의 학습에 도움이 된다는 것**입니다. 반면 “피싱에 보편적인 공통 무늬를 발견했다”, “CNN이 URL의 의미를 이해했다”, “누출 가능성을 제거했다”까지 말할 근거는 부족합니다.

학부 졸업생이라는 점 때문에 연구의 기준이 달라지지는 않습니다. 하지만 처음 시작한 개인 연구에서 길이 매칭, 도메인 분리, 대조 모델, 외부 검증까지 진행했다는 것은 분명한 강점입니다. 이제 필요한 것은 실험을 무작정 늘리는 것보다 **코드가 실제로 측정한 것과 논문의 주장을 정확히 맞추는 작업**입니다.

검토 기준은 저장소의 [`fa8434d` 커밋](https://github.com/bnbong/CNN-QR-phishing-detector/tree/fa8434d5e1f718c84efa9fbb8454bef136a8e5c6)입니다. 공개 코드·설정·노트북, 설계 및 리뷰 문서, 결과 CSV·JSON을 대조했습니다. Python 파일 46개의 구문과 결과 JSON 93개의 파싱을 확인하고 표 생성 스크립트도 실행했습니다. 다만 원본 데이터와 체크포인트를 이용한 **전체 학습·예측 재현 및 테스트 스위트 실행은 하지 않았습니다.** 아래의 코드상 문제와, 실제 성능에 미친 영향이 아직 확인되지 않은 문제를 구분해서 읽어주세요.

**1. 연구의 가장 좋은 부분은 “높은 점수의 이유”를 의심했다는 점입니다.**

정상 URL과 피싱 URL의 길이가 다르면 QR의 크기나 패딩만 보고도 분류할 수 있습니다. 그래서 높은 정확도가 곧 피싱 특성을 배웠다는 뜻은 아닙니다.

현재 구현은 이 문제를 상당히 진지하게 다룹니다.

* 도메인 그룹을 먼저 분리한 뒤 **각 train/validation/test 내부에서 길이를 매칭**합니다.
* 정규화 뒤 중복과 라벨 충돌을 제거합니다.
* 텍스트 벡터라이저는 train에서만 학습합니다.
* 모델 선택과 임계값 선택에는 validation을 사용합니다.
* 외부 평가에서는 기존 모델과 텍스트 기준선을 다시 학습하지 않고 적용하는 경로를 마련했습니다.

특히 “전체 데이터에서 길이를 맞춘 뒤 분할하면 각 split에서는 다시 길이가 불균형해질 수 있다”는 문제를 코드에서 처리한 점은 좋습니다. 연구 방법의 실질적인 강점입니다. [분할 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/splits.py), [실행 파이프라인](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/runner.py)

다만 길이의 **단독 예측력**을 제거했다고 해서 길이가 다른 특징과 상호작용하는 효과까지 없어진 것은 아닙니다. 논문에는 “길이 주변분포를 일치시켰다”라고 정확히 쓰는 것이 좋습니다.

**2. 가장 먼저 고칠 코드 문제는 motif 선정과 평가의 분리입니다.**

현재 흐름은 다음과 같습니다.

1. 시드마다 서로 다른 train/test 분할을 만듭니다.
2. 여러 시드의 train 데이터를 합쳐 공통 motif 목록을 선정합니다.
3. 그 목록을 각 시드의 test 절제 실험에 사용합니다.

문제는 **시드 0의 test URL이 시드 1의 train에는 들어갈 수 있다는 것**입니다. 그러면 시드 0에서 평가할 URL의 라벨이 다른 시드를 통해 motif 선정에 영향을 줄 수 있습니다.

`run_motifs()`가 여러 시드의 학습 자료를 모아 `enrichment.json`을 만들고, `run_occlusion()`이 그 파일 하나를 모든 시드에 사용하는 경로에서 확인됩니다. [runner.py](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/runner.py), [motifs.py](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/motifs.py)

**이 문제는 CNN 주 분류 성능 자체와 구분해야 합니다.** 직접 영향을 받는 것은 “어떤 motif를 골랐으며 그것을 건드렸을 때 얼마나 성능이 떨어지는가”라는 분석입니다. 실제 중복 규모와 결과 변화량은 원자료로 확인해야 합니다.

가장 간단한 수정은 **각 시드의 train에서만 motif를 선정하고, 해당 시드의 test에서만 절제하는 것**입니다. 별도의 고정 discovery/test 분할을 두는 방법도 가능합니다.

**3. motif 절제의 무작위 대조군에는 비교 조건의 비대칭이 있습니다.**

`occlude_stratum()`에서는 motif 표적 개입은 한 번 적용하지만, 무작위 개입은 여러 번 수행한 **예측 로짓을 평균한 뒤 AUROC를 계산**합니다. [occlusion.py](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/occlusion.py)

이것은 다음 두 값을 비교하는 셈입니다.

* 특정 부위를 한 번 훼손한 입력에 대한 성능
* 서로 다르게 훼손한 여러 입력의 예측을 평균한 성능

예측 평균은 무작위 훼손의 영향을 상쇄할 수 있습니다. 따라서 현재 방식은 무작위 대조의 성능 저하를 작게 보이게 할 가능성이 있습니다.

권장하는 수정은 다음과 같습니다.

* 무작위 개입 **반복마다 AUROC를 계산**한 뒤 효과의 평균과 분포를 보고합니다.
* 동일 test에서 **표적 개입과 무작위 개입의 차이 자체**에 대한 쌍체 신뢰구간을 계산합니다.

현재처럼 각각 원본과 비교하는 것만으로는 두 개입의 차이가 통계적으로 확인되었다고 할 수 없습니다.

또 “4~12배 큰 성능 저하”라는 표현은 무작위 대조의 하락폭이 0에 가까워 비율이 불안정합니다. **절대 AUROC 차이와 그 신뢰구간**을 중심으로 보고하는 편이 낫습니다. 시드별 CI 경계의 평균도 통합 효과의 95% CI로 읽히지 않도록 분리해야 합니다.

**4. 외부 검증의 “편향 방향이 반대”라는 설명은 실제 결과와 맞춰 다시 확인해야 합니다.**

이 부분은 논문의 해석에 중요합니다.

보고서는 대략 “내부 데이터에서는 정상 URL에 경로가 적고 피싱 URL에 많지만, 외부에서는 그 방향이 뒤집혔다”고 설명합니다. 그런데 저장된 **매칭 후 v2 진단값**은 다음과 같습니다.

| 경로가 있는 URL 비율   |     정상 |     피싱 |
| --------------- | -----: | -----: |
| WebPhish 참조 데이터 | 99.75% | 44.31% |
| 외부 평가 데이터       | 86.83% | 33.73% |

**둘 다 정상 쪽의 경로 보유율이 높습니다.** v3·v4도 같은 방향입니다. 적어도 실제 평가에 사용된 층에서는 “편향 방향이 반대”라는 설명이 성립하지 않습니다. [외부 v2 결과 JSON](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/reports/transfer/external_primary_2026-09-08/a_fixed/norm-exact-data_only-fixed-small_cnn/v2/results.json)

`bias_direction_ok()`도 두 데이터셋 모두에서 *피싱 쪽 경로 보유율이 더 높은 경우*만 실패 처리합니다. 따라서 반대 방향의 공통 편향은 통과합니다. [transfer.py](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/transfer.py)

여기서 필요한 것은 다음입니다.

* 원본 → 정규화 → 층화 → 길이 매칭 단계별 클래스·경로 통계 확인
* `spam/ham` 매핑과 원본 컬럼 정의 재확인
* 경로 유무·깊이·구분자 비율만 사용하는 기준선 추가
* 가능하면 길이와 경로 유무를 함께 맞춘 민감도 분석

이것이 라벨이 뒤집혔다는 증거는 아닙니다. **현재 문서가 실제 분석 대상의 특성을 잘못 설명하고 있을 가능성**을 확인해야 한다는 뜻입니다.

외부 전이가 남았다는 관측은 유효할 수 있지만, 그것이 공통된 출처·구조 차이로 설명되는 정도는 아직 불분명합니다.

**5. “통계적으로 차이를 찾지 못했다”와 “차이가 없다”를 구분해야 합니다.**

현재 가장 강하게 수정해야 할 문장은 템플릿 누출에 대한 결론입니다.

`_campaign_verdict()`는 CI 하한이 0 이하이면 “누출 무시 가능”으로 판정합니다. 하지만 이 규칙은 예를 들어 CI가 `[-0.10, +0.30]`처럼 큰 양의 효과까지 허용해도 같은 판정을 내립니다. [판정 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/runner.py)

실제 전체 test의 CI는 이 예시보다 훨씬 좁습니다. 그렇더라도 현재 확인된 것은 다음에 가깝습니다.

> 정의한 템플릿 분리 방식과 평가 집합에서, 누출 허용에 따른 전체 AUROC 상승을 검출하지 못했다.

“무시 가능”을 주장하려면 **실질적으로 중요한 최소 차이**를 정하고, 그보다 작은 효과라는 것을 보여줘야 합니다. 예를 들어 허용 가능한 상승폭을 미리 정한 후 상한을 평가하는 방식입니다.

더구나 실제 누출 기회가 있는 test 행이 38 / 35 / 15개뿐이고, 해당 부분집합의 CI는 넓습니다. 따라서 “phishing kit 암기 가능성을 배제했다”는 결론은 과합니다. URL 템플릿 클러스터도 실제 공격 캠페인의 완벽한 정답 라벨은 아닙니다. [캠페인 결과](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/reports/campaign/results.json)

같은 이유로 다음 표현도 고쳐야 합니다.

| 현재 표현의 취지             | 권장 표현                              |
| --------------------- | ---------------------------------- |
| 라벨 셔플이 0.5이므로 누출은 없다  | 해당 음성 대조에서 이상 성능은 관측되지 않았다         |
| URL 어휘 복원은 기각되었다      | 사용한 프로브와 판정 기준으로 복원 증거를 확보하지 못했다   |
| 옛 G의 차이는 test 교체 효과였다 | 옛 비교는 test 교체 효과와 누출 효과를 분리할 수 없었다 |
| CNN은 특정 문자열을 이용하지 않는다 | 특정 문자열 이용 여부는 현재 분석으로 확정할 수 없다     |

**6. 어휘 프로브는 “정보가 있는가”보다 더 엄격한 질문을 검사합니다.**

현재 유의 판정은 학습 CNN의 프로브가 셔플 기준선뿐 아니라 **무작위 초기화 CNN의 프로브까지 CI 수준에서 넘고, 모든 시드에서 성공할 것**을 요구합니다.

이것은 단순히 “문자 정보를 읽어낼 수 있는가?”보다 **“학습을 통해 문자 정보를 더 잘 읽을 수 있게 되었는가?”**에 가까운 질문입니다.

실제로 보고서에는 `ngram:jp.` 예측 AUROC가 학습 표현에서 0.909, 미학습 표현에서 0.849인 예가 있습니다. 최종 기준을 통과하지 못했다고 해서 해당 정보를 전혀 읽어낼 수 없다는 뜻은 아닙니다. [프로브 결과 설명](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/docs/REPORT.md), [프로브 판정 코드](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/probes.py)

논문에서는 다음을 분리하세요.

* 표현에 어휘 정보가 선형으로 접근 가능한가?
* 피싱 분류 학습이 그 접근 가능성을 높였는가?
* 그 정보가 실제 분류 결정에 사용되는가?

세 질문은 서로 다릅니다. 또한 프로브 입력은 코드상 **GAP 이후 128차원 벡터**입니다. 보고서의 “GAP 직전 128차원” 표현도 수정해야 합니다.

**7. 성능 차이를 곧바로 신호의 구성 비율로 해석하면 안 됩니다.**

보고서에는 “문자 조성 + 국소 비트 패턴 + 넓은 범위의 순서 구조”라는 설명이 있습니다. 그럴듯한 가설이지만, 현재 비교만으로 이 세 성분을 분해했다고 볼 수는 없습니다.

구체적으로는 다음과 같습니다.

* **BitMLP도 위치 정보를 사용할 수 있습니다.** 고정 위치 셔플 후 재학습할 수 있다는 것과 위치를 못 쓴다는 것은 다릅니다.
* byte-hist 모델과 CNN의 점수가 비슷해도 두 모델이 같은 정보를 쓰는지는 알 수 없습니다.
* 3×3 패치 LR보다 CNN이 좋다는 차이에는 수용영역뿐 아니라 비선형성, 모델 용량, 학습 방식도 섞입니다.
* 코드워드 셔플은 QR 코드워드의 다중집합을 보존합니다. 이것은 **원본 URL 바이트의 히스토그램을 보존하는 실험과 동일하지 않습니다.** 헤더·패딩·오류정정 코드워드 등이 함께 들어 있기 때문입니다.

따라서 “원래 배치에 유용한 구조가 있다”는 결론은 좋지만, “그 차이만큼이 URL 순서 정보의 기여분이다”는 표현은 피해야 합니다. [모델 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/models.py), [코드워드 셔플](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/motifs.py)

또 URL 전체 소문자화와 말미 `/` 제거는 경로·쿼리의 의미까지 바꿀 수 있습니다. 현재 연구의 대상을 **“정규화된 URL 문자열에서 합성한 QR 격자”**로 명확히 한정하는 것이 정확합니다.

**8. 결과 기록과 통계 구현에도 보완할 부분이 있습니다.**

| 확인한 사항                                 | 의미와 조치                              |
| -------------------------------------- | ----------------------------------- |
| 외부 순열 횟수는 문서에서 2,000회, JSON에서 200회     | 실제 실행값으로 문서를 수정하거나 재계산              |
| 외부 CNN은 5시드 평균, 기준선은 첫 성공 시드           | 같은 시드별 학습 자료와 test로 비교한 뒤 차이의 CI 제시 |
| 외부 v2 CNN 평가 15,480행, motif 기준선 8,000행 | 동일 cohort 비교를 추가하거나 표본 수 차이를 표에 명시  |
| 외부 순열은 크기가 다른 그룹의 라벨을 반복 복사            | 일반적인 행 라벨 순열이 아니므로 귀무 모형과 타당성 검토 필요 |
| 노트북 설치 대상이 `@main`                     | 논문 재현용 실행은 커밋을 고정                   |
| OpenPhish 기록에 전체 180개 중 마지막 5개 SHA만 저장 | 전체 커밋 목록과 실제 수집 시각 범위를 기록           |

특히 외부 순열 함수는 작은 예제로 확인했을 때 **양성 라벨 총수가 바뀔 수 있었습니다.** 무조건 잘못된 귀무 시뮬레이션이라는 뜻은 아니지만, “정식 순열 검정”이라고 부르려면 무엇을 교환 가능하다고 가정했는지 설명해야 합니다. [외부 순열 구현](https://github.com/bnbong/CNN-QR-phishing-detector/blob/main/qrphish/transfer.py)

`pseudo-p`라는 이름을 붙인 투명성은 좋습니다. 그러나 이름을 바꾼 것만으로 정식 p값의 성질이 생기지는 않고, Holm 보정도 그 문제를 해결해 주지는 않습니다. 이 부분은 교수님께 통계 검토를 요청하기 좋은 항목입니다.

**9. 논문의 차별성은 “CNN으로 QR을 분류했다”에 두면 약합니다.**

관련 선행연구가 이미 있습니다. 예를 들어 Trad와 Chehab의 연구는 URL 추출 없이 QR 구조와 픽셀 패턴으로 quishing을 탐지하는 접근을 제시합니다. 따라서 “디코딩 없는 QR 분석을 처음 제안했다”는 주장은 피해야 합니다. [관련 논문](https://arxiv.org/abs/2505.03451)

준혁 님 연구의 차별성 후보는 다음입니다.

> QR 기반 피싱 분류의 성능을 길이·생성 조건·공간 배치·국소 패턴·외부 전이로 나누어 검토하고, 그 성능이 보편적인 시각적 서명을 의미하는지 평가한다.

보안 머신러닝에서 데이터 편향과 부적절한 평가가 성능과 해석을 부풀릴 수 있다는 문제는 중요한 연구 주제입니다. 관련 연구를 쓸 때 [Dos and Don’ts of Machine Learning in Computer Security](https://www.usenix.org/conference/usenixsecurity22/presentation/arp)와 [TESSERACT](https://www.usenix.org/conference/usenixsecurity19/presentation/pendlebury)를 함께 읽으면 연구의 위치를 잡는 데 도움이 됩니다.

다만 이번 선행연구 확인은 완전한 문헌조사가 아니므로, 정확한 신규성은 관련 논문들의 통제 조건을 표로 비교한 뒤 확정해야 합니다.

---

**논문을 위해서는 다음 순서로 진행하는 것이 좋겠습니다.**

| 우선순위 | 할 일                            | 목적                       |
| ---- | ------------------------------ | ------------------------ |
| 1    | motif 선정·평가 분리와 무작위 절제 대조 수정   | 핵심 해석 분석의 신뢰성 확보         |
| 2    | 경로 비율·라벨·전처리 단계별 진단 재확인        | 외부 전이의 대안 설명 확인          |
| 3    | 같은 시드·같은 test로 기준선 비교 및 통계 재정리 | 비교의 공정성과 불확실성 명확화        |
| 4    | “없다·기각·원인이다” 같은 과한 결론 수정       | 증거에 맞는 논문 주장 정립          |
| 5    | 선행연구 비교표와 짧은 논문 초안 작성          | 신규성과 논리 구조 정리            |
| 6    | 필요할 때 외부 motif 절제·추가 통제 진행     | 교수님 피드백에 따라 가장 중요한 빈칸 보완 |

촬영 QR, 더 큰 CNN, 역방향 전이, 혼합 학습을 전부 해야 논문을 쓸 수 있는 것은 아닙니다. **정규화된 합성 QR 격자에 관한 통제 연구로 범위를 한정하면 됩니다.** 다만 실제 탐지 시스템의 실용성을 주장하려면 자연스러운 QR 생성 조건과 촬영 환경, 오탐률 평가가 필요해집니다.

초안은 다음 흐름이면 충분합니다.

1. **서론:** QR 분류 성능이 공통 시각 패턴의 존재를 뜻하는가?
2. **관련 연구:** 기존 QR 분류 연구와 통제·일반화 평가의 차이.
3. **방법:** 데이터, 정규화, 길이 매칭, 분할, 모델, 통계.
4. **결과:** 신호 존재 → 공간 배치 효과 → 국소 패턴 → 외부 전이.
5. **논의·한계:** 확인한 사실, 가능한 설명, 아직 구분하지 못한 설명.
6. **결론:** 제한된 조건에서의 판별 신호와 일반화의 범위.

과거의 실패는 서론의 짧은 동기로 활용할 수 있습니다. 다만 과거 Accuracy 0.8710과 현재 AUROC 0.872는 지표와 실험 조건이 달라 직접 비교하면 안 됩니다. “AI 성능이 좋아져 실험이 성공했다”보다 **“초기 실험에서는 검증하기 어려웠던 가설을 통제 실험으로 다시 평가했다”**가 연구의 발전을 더 정확히 설명합니다.

교수님께는 완벽한 논문을 만든 뒤 연락할 필요는 없습니다. 위의 핵심 수정과 짧은 초안을 준비한 다음, **① 통제 연구로서의 기여가 충분한지, ② 통계 설계가 타당한지, ③ 어떤 추가 실험이 가장 필요한지**를 구체적으로 여쭤보세요.

준혁 님이 직접 설명할 수 있어야 할 핵심은 세 문장입니다.

* **길이만 보고 맞힌 것은 아닌가?** → split별 길이 매칭과 길이 기준선으로 확인했다.
* **CNN이 QR의 배치를 이용하는가?** → 위치를 섞었을 때 CNN과 MLP의 반응이 달랐다.
* **그렇다면 보편적인 피싱 무늬인가?** → 외부 전이는 일부 남지만, 특정 무늬의 보편성은 아직 입증하지 못했다.

이 세 문장을 근거와 한계까지 설명할 수 있다면, 교수님과 첫 연구 논의를 시작할 준비는 되어 있습니다.
